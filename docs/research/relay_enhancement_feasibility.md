# 通知、空教室、水电的中继加速与增强包研究

日期：2026-10-31。性质：**研究与实施建议，未部署、未做真实学校性能测试**。

本报告支撑 [ADR-042](../adr/adr_042_providers_pages_enhancements.md) 与[平台演进计划](../planning/platform_evolution.md)。运行中行为以代码和已接受的 ADR-034～040 为准；下文的 provider 绑定、增强包隔离、缓存服务协议都是待实施设计。自动测试和本报告不构成人工安全签收。

## 1. 结论

统一查询确实有减少重复请求的空间，但收益来自**同一授权范围内相同查询的合并、缓存与有界预取**，不是增加一次网络转发本身。

| 数据 | 当前证据 | 适用部署 | 建议优先级 |
|---|---|---|---|
| 公开通知 | 西电脚本独立访问教务处公开网页，不附带认证会话 | 无凭据的公共采集任务 + 公开快照/CDN | 第一阶段试点 |
| 空教室 | 西电脚本经 E-Hall 会话，按楼栋、学期、周/日期查询；结果可能与身份权限有关 | 默认客户端；取得学校共享查询/发布授权后，校内中继按授权范围聚合 | 第二阶段，有条件实施 |
| 宿舍水电 | IDS → OAuth → NodeID → 账户表具列表 → 指定表具历史；数据属于账户/房间 | 默认客户端缓存；校内中继仅在独立授权方案落地后按身份隔离 | 第三阶段，先做本地优化 |

**不能使用一个普通学生账号替全校查询，再把结果当作公开数据发布。** 空教室“多人可能看到相同结果”不等于学校允许匿名再分发；知道房间号或表具 ID 也不等于拥有查询权限。增强包首先是可选择的能力提供者，不是凭据共享或任意代理的授权。

## 3. 外部证据及其限度

HTTP 共享缓存要区分鉴权、`private` / `no-store`、`Vary`、缓存年龄和条件校验；`Set-Cookie` 本身并不会自动阻止 HTTP 缓存。因此不能只凭“GET 请求”或“有无 Cookie 响应头”分类数据。本项目应采用更严格的显式公开数据清单，禁止凭据参与公共采集。[RFC 9111 §3、§4、§7.3](https://www.rfc-editor.org/rfc/rfc9111.html)

`stale-while-revalidate` 允许限时返回旧内容同时更新，`stale-if-error` 允许在限定失败条件和时间内使用旧内容。这可以改善通知阅读体验，不能把旧余额、旧教室占用或设备状态标作实时。[RFC 5861 §3–4](https://www.rfc-editor.org/rfc/rfc5861.html)

北京大学教务部明确要求到校内门户查询空闲教室，说明该类数据不能跨校一概认定为公开接口；这不是西电授权状态的证据。[北京大学教务部：空闲教室查询](https://dean.pku.edu.cn/web/student_info.php?id=47&type=12)

本次可读取[西电新闻网](https://news.xidian.edu.cn/)的公开栏目，但无法通过研究浏览工具成功获取 `https://jwc.xidian.edu.cn/index.htm`。因此西电教务处首页的匿名调用方式依据本仓代码与夹具，**线上可达性、缓存头、再分发许可、robots 及运维允许频率仍待试点核实**；新闻网的可读性不证明教务处接口当前可用，也不能替代教务通知源。搜索结果中的非学校镜像站不作为学校协议或授权依据。

## 4. 两种部署边界

### 4.1 公共匿名加速

```mermaid
flowchart LR
  S[经确认的学校公开网页] --> F[固定匿名采集任务]
  F --> V[解析与 schema 校验]
  V --> P[原子发布公开快照]
  P --> C[静态托管或 CDN]
  C --> E[客户端通知增强 provider]
  E --> H[宿主选源与新鲜度展示]
```

采集任务只访问固定源清单，无学生 Cookie、Token、SSO 或账户登录。公开快照可以重建，不建立用户数据库。原有 `server/src/public` 分发端点保持自己的职责；新的公开数据路径应使用独立部署和明确的数据发布配置，避免误把 bundle 的长时间 immutable 缓存用于业务快照。

不接受任意 URL 作为回源参数；详情仅从已知通知条目映射出目标。逐跳校验源站清单，禁止降级到登录页、任意内网地址或将未净化响应头、调试信息放入快照。上游返回鉴权页、验证码、schema 不符或疑似个人信息时停止发布该批，保留此前仍允许使用的快照并显示年龄。

### 4.2 校内授权中继

中继放在学校认可的环境，客户端访问授权与学校上游访问授权是两个独立条件。按请求校验身份、能力、资源和授权代际，不因命中缓存跳过授权。校内服务账号只在学校明确授予的范围内采集，不能由个人学生账号临时冒充。

既有 campus 设计要求凭据/私密结果零落盘。第一版建议继续采用单次凭据或客户端完成认证、短期内存结果；校级共享快照仅来自学校明确批准的共享数据源。持久化个人历史、长期服务账号托管或向公网发布校内结果都必须形成独立决策，不能视为“加一个缓存”的实现细节。

同一台物理机也必须拆分公共服务与校内服务的进程、配置、密钥访问和日志；网络位置本身不能证明权限隔离。校内中继故障时，仅回退用户自己的客户端直连；不能改道到公共代理。

## 5. 查询语义、缓存和失效

以下 TTL 是**试点初值，不是测量结论或学校服务承诺**。学校缓存约束、数据分类和授权失效优先于 TTL。

| 项目 | 公开通知 | 空教室 | 水电 |
|---|---|---|---|
| 基础缓存键 | school + source + capability + schemaVersion + parserVersion + 规范化参数 | 前项 + 授权受众/身份 + 学期 + 校区/楼栋 ID + 日期/周次 + 时区 | 前项 + 当前身份 + 授权代际 + meterId + type/unit + 实际 from/to |
| 建议刷新 | 列表 5 分钟；热点详情 30 分钟；详情被列表更新触发提前校验 | 共享授权成立后，当日占用 1～2 分钟；楼栋目录 24 小时 | 表具/余量 1～5 分钟；历史窗口 30 分钟；打开页面按需更新 |
| 旧数据 | 列表最长 1 小时用于故障阅读；详情最长 24 小时；显示来源和时间 | 过期后只作参考，不能用旧值保证“可用”；unknown 不变成 available | 历史仍标原 readAt；余量标查询时间，失败不覆盖为零 |
| 隔离 | 只收明确公开源；内部通知不得落同一缓存 | 未确认共同授权范围时按用户隔离；角色不同不合并 | 默认账户隔离；同宿舍也不自动合并 |
| 撤销/失效 | 撤稿、纠错、源权限变化立即停发/清除；解析器或 schema 改版换键 | 调课、考试、临时借用、学期/校历变化；用户权限撤销即时失效 | 换宿、表具重绑、账号退出、授权撤销；充值后只读刷新但不推定余额已变 |
| 禁止缓存的内容 | 登录响应、原始鉴权头、含秘密链接 | 私人课表、学生身份、未批准的全量占用原始响应 | Cookie/OAuth code/NodeID/签名、账密、设备控制与支付结果 |

补充规则：

1. 默认参数先解析为确定值再构造查询键。“当前学期”“今天”“最近一月”不能长期使用空参数键；学期默认值与本科/研究生身份差异要保留。
2. 空教室可以按**楼栋 + 日期/学期周次**采完整占用矩阵，再按节次、roomId、onlyAvailable 投影；只在确知原始返回完整时合并。当前字段有模糊 building/room 语义，首个增强 provider 应要求稳定 ID 或先由主 provider 解析，不能各自猜测。
3. `freshness.fetchedAt` 保留实际成功获取/校验来源的时间；CDN 命中和本地读取不能重置为现在。保留学校原始 `readAt`、`updatedAt`、日历日语义，它们与查询时刻不同。
4. 解析失败、权限错误、取消不是空数组成功；不写入成功缓存。短时熔断状态与成功数据分开存储。
5. 公共响应拒绝用户身份参与查询；校内私密响应采用 `private, no-store` 禁止代理层共享，客户端默认也不持久化该响应；若需要离线私密缓存，必须在协议和授权中另行定义，不以应用缓存绕过 no-store。服务器内存按身份隔离并在退出/撤销时淘汰。
6. HTTP 条件校验可使用 ETag / Last-Modified；不支持时只按预算取完整响应。上游 `no-store` 等指令与源站授权限制不能因生成了 JSON 快照而被绕过。未知 `Vary` 维度不得合并。

## 6. 增强包如何接入主学校包

统一术语与 ADR-042 对齐：主学校包提供默认学校流程；能力 provider 是某个包对具体 capability 的实现；增强包提供额外或替代的 provider。宿主选择 provider，学校包之间不任意 import、共享运行时或无限递归调用。

### 6.1 需要新增的能力，而非现有 manifest 字段

下面是设计信息表，**不是可直接安装的 `.elecon.json` 示例**：

| 信息 | 通知增强包示例 | 宿主需要验证 |
|---|---|---|
| 增强包身份 | 独立 packageId、version、digest、publisher 描述 | 不与主包 ID 冲突；安装/更新重新确认 |
| 适用学校和依赖 | 精确 schoolId；可选主包 ID 和版本范围 | 同校；依赖满足；禁用/卸载主包后的行为明确 |
| 提供能力 | notice.list、notice.detail；各自 params/output 版本 | 注册能力存在，输入输出契约兼容，支持参数范围可查询 |
| 数据集范围 | xidian-jwc；相同条目 ID 与 sourceSystem | 防止把相同数字 ID 的另一通知源当同一条记录 |
| 网络范围 | 单个已确认公共快照 origin | 不继承主包学校域名和浏览器权限 |
| 认证需求 | anonymous | 必须由新 SDK/宿主 profile 强制无凭据、无浏览器；仅写声明不足以隔离 |
| 选源 | 用户按能力启用增强 provider | 安装顺序不改变现有绑定；冲突可见，可恢复主 provider |
| 回退 | 公开通知读取失败可选择主 provider | 相同查询语义与隐私范围；总截止时间内最多一次；无循环 |

当前 SDK 2～5 可在学校范围内读取其他 namespace 的凭据，不能直接承载上述 anonymous 权限保证。需要新 SDK/profile，拒绝旧宿主运行它，明确凭据能力缺席，并验证调用通道、日志和浏览器均无绕过。对既有完整受信学校包保持原有信任解释，不用新增强包声明静默降低或扩大其权限。

### 6.2 用户实际使用流程（待实现）

1. 用户已装主学校包，在“能力来源”页看到通知默认来自学校直连。
2. 导入通知增强包；固定安装页展示运营者、适用学校、快照域名、数据更新上限、anonymous profile 和 digest，确认后安装。
3. 用户显式为通知列表/详情选择增强 provider。首版要求 list/detail 成组兼容；只覆盖列表的增强包不能把裸 id 交主 provider。后续有显式且经验证的实体映射时，才允许跨 provider 详情。
4. 课表、通知列表、通知详情等页面只请求领域能力。通知页展示原始来源、上次取数时间与当前陈旧状态，提供“本次直连刷新”。增强包不会新建一套不同的通知 UI。
5. 中继超时允许一次有界回退；跨隐私边界、认证失败、参数不支持、语义版本不符时不自动换源。主包已有数据不能被另一 provider 的晚到响应覆盖。
6. 禁用/卸载/更新增强包使在途调用失效，清理该 provider 的缓存与绑定；用户可恢复主包查询。不要静默选择另一个陌生 provider。

只读增强包默认不取得主包凭据。如未来水电增强需要主包身份，优先让宿主以显式、有限的能力依赖调用主 provider 并传递标准数据，不传完整凭据；仍需单独授予私密结果读取权限。跨包调用设计必须包含依赖图无环、最大深度、累计请求/时间预算、错误归属、取消传播，首期直接禁止链式调用更容易验收。

## 7. 公开通知试点的分步落地

| 步骤 | 交付物 | 完成条件 |
|---|---|---|
| R0：源核实 | 仅对固定教务处首页进行低频匿名核验，记录可达性、内容分类、响应缓存要求及允许抓取/发布条件 | 无学生凭据；确认列表/详情可公开再分发；失败则继续用合成夹具 |
| R1：采集器 | 独立公共任务；固定源、解析器版本、大小/时间/请求限制；列表与按需详情快照 | 合成夹具输出与客户端 parser 一致；失败不发布半成品；不得执行任意用户源码 |
| R2：快照服务 | 独立 HTTPS 静态数据端点，原子替换、ETag、短缓存、过期淘汰和停止发布开关 | 只含公开归一化数据；请求和日志无账户信息；不会碰旧 public 分发白名单 |
| R3：宿主与增强包 | ADR-042 落地后的 provider resolver、anonymous profile、能力来源设置、原来源新鲜度传递 | 强制权限隔离、契约版本协商、显式绑定、取消与卸载回归通过 |
| R4：端到端试用 | 本地合成源 → 采集 → 快照 → 增强包 → 现有通知页，再做经许可的低频真实只读试用 | 列表/详情同源；离线/恢复/撤稿/更新/禁用可演示；记录实测差值与限制 |

快照拟采用带明确版本的外包装，记录 `schoolId`、数据集/能力、schemaVersion、采集器版本、规范化查询、成功取数时间、有效期、归一化 data。复用现有业务 schema，但**现有数据信封没有全部 provider/查询绑定信息，不能声称开箱即用**；协议须随 ADR-042 的契约变更落地。新鲜度不应通过向 `notice.list.data` 塞入任意展示字段解决。

通知列表先限定 `page=1, size<=100, category=academic/省略`，与当前主包行为一致。主包支持范围外的请求应返回明确“不支持”，不能把首页切片伪装成第二页。通知详情以列表授权的数据集 + id + 已验证 URL 找到原文；附件维持链接形式，不默认建立文件镜像。

首个部署不需要数据库或消息队列：一个有界采集任务、公开 JSON 快照与静态托管即可。是否需要多实例锁、持久化公开索引、队列或签名快照，由试点需求和威胁模型决定。HTTPS 与安装 digest 只保护各自链路和代码，不能证明运营者发布的数据必定正确；UI 保留学校原文入口。

## 8. 压力预算、收益计算与验证

### 8.1 试点预算

初值：每个源站最多 1 个活动采集请求；全局最多 2 个；单请求 10 秒、单轮 30 秒；公开正文最多 2 MiB；每轮最多 5 个上游请求。列表每 5 分钟刷新，详情只取近期用户访问过或列表发现变更的条目；不扫全站。重试最多一次且仍计入预算，遇 429 尊重 Retry-After，连续失败退避至 15 分钟。实际允许频率以学校要求中更严格者为准。

同缓存键并发使用 single-flight（一个在途请求，多调用者等结果）；不同键有队列上限与拒绝策略。静态发布有一个调度 owner；多副本不能各自按相同周期抓学校。刷新增加抖动，客户端回退也有退避，避免中继故障时所有终端同时回源。

若同一个公开列表每分钟有 N 次客户端读取，每 5 分钟采集一次、每次一页，则理想稳态上游列表请求从 `5N` 降为 `1` 次/5 分钟。**这是模型上界**：详情、失败重试、不同参数和低复用率均会降低收益。转发未命中路径增加一跳，对私密水电这类低共享查询可能更慢，因此不能预先承诺几倍加速。

### 8.2 当前可复现检查

现有通知解析测试使用合成网页，不联网，可从仓库根目录运行：

```bash
node --test school-scripts/xidian/tests/notices.test.mjs
```

本次执行结果：7 项通过、0 项失败。该命令验证现有归一化、URL 约束与附件行为；**它不验证尚未实现的中继、缓存、增强包权限或端到端性能**。开发期可直接复用这些合成页面搭本地源站，避免用真实学生数据制作夹具。

### 8.3 待实施的可复现实验

准备本地合成上游（固定延迟 500 ms、响应版本计数器、可切换 200/304/401/429/500、修改/撤稿和失效开关），相同硬件、相同样本分别跑直连与中继。冷缓存、热缓存、TTL 边界、上游故障各运行 100 次，并发分别为 1/10/50；每场景单独报告 p50/p95、样本数、错误率、上游请求数、数据年龄和命中率，原始匿名计数保存为验收附件。学校生产环境不跑负载实验。

| 验收项 | 可判定目标（不是本次结果） |
|---|---|
| 请求合并 | 同一键、同一刷新代际的 50 个并发读取最多触发 1 次上游采集；失败路径也不形成 50 次重试 |
| 热缓存收益 | 在上述 500 ms 合成上游中，热缓存 p95 至少降低 50%；如未达标需分析开销后再决定部署 |
| 参数正确性 | 不同学校/数据源/schema/日期/时区/身份绝不串键；规范化后等价参数一致，不等价参数不合并 |
| 权限正确性 | 无授权、撤销授权、伪造 meterId、跨校/跨身份访问均拒绝，即使已有缓存；anonymous provider 不能读任何凭据 |
| 一致性 | direct 与缓存的领域结果相同；查询时间、学校观测时间、缓存年龄分开；过期结果不会显示为实时 |
| 恢复与回退 | 中继失败后最多一次同语义回退；取消/切校/更新后晚到结果不写回；写操作从不进入重试或缓存路径 |
| 公开面 | 日志/快照无秘密或身份数据；登录页/Set-Cookie/带 token URL 不被传播；不接收任意回源地址 |
| 关闭试点 | 一个开关停止采集和发布，增强包可禁用，主包仍能独立查询 |

## 9. 暂不做的扩展及启动条件

空教室先优化主包内目录复用、确定参数与本地缓存；拿到学校共享读取授权后再做校内按楼栋/日期合并。水电先优化同账户会话复用和相同窗口请求合并，不批量扫描宿舍。没有正式凭据托管与数据访问方案时，不启用校内水电代理。

论坛公开帖子或图书馆公共目录未来可复用公共查询缓存设施，但论坛草稿、私信、删除/点赞/发帖、借阅记录、预约/续借必须按其读取/写入与身份语义另行定义。通知“新增一条”与论坛“编辑/删除一帖”不是相同失效模型，不能仅套用相同列表模板即宣称兼容。

进入真实试点前待核实：教务公开源当前访问情况与采集发布条件、空教室跨角色可见范围、校内服务账号授权方式、运行环境可达性、日常维护人和停服联系人。部署和性能应留独立证据，不能将本报告状态改写为“增强包已可用”。
