# 空教室来源、粒度与筛选职责讨论

日期：2026-11-04。状态：**讨论记录，首片由 [ADR-082](../adr/adr_082_script_query_forms.md) 接受并实施，异步字段与离线首屏续片见 [ADR-083](../adr/adr_083_deferred_query_fields.md)**。本文保留 HAR 证据和后续设计方向；当前接口以 ADR、schema 和[作者手册](../wiki/interactions.md)为准。任务状态只在[统一实施计划](../planning/implementation.md)维护。

ADR-083 将 query.controls 升至 2.1：西电基础表单与校区/楼栋切换使用注明核对日期的包内目录，可选教室类型通过独立 load 补充，未返回时不阻塞基础查询；最终业务查询仍验证实时目录。时间默认值由学校脚本提供，来源精度和课间未知语义不变。该续片是交互与加载策略调整，**没有新增 HAR 证据或真实学校验收**；下方样本统计仍是首次离线研究的同一份记录。

## 先区分三种“来源”

1. 执行来源：安装包、批准 digest、身份；由核心附加和校验，脚本不可自行伪造。
2. 业务来源：教务空教室模块、楼栋字典、借用明细等；由脚本解释，不能只用一个包名称代替全部证据。
3. 时间与精度：源站更新时间、实际采集时间、查询覆盖范围、源站节次还是推导分钟区间；分别记录。源站未提供更新时间就保持缺失，不能用查询完成时间覆盖 `updatedAt`。

一个教室的类型和座位信息、分节占用以及借用说明可能来自不同响应。允许分层加载和各自失败；详情不可用不应把已知占用改成空闲，旧详情也不能冒充本次查询结果。

## 建议的职责分配

| 内容 | 核心/契约责任 | 学校脚本责任 |
|---|---|---|
| 来源与生命周期 | 绑定包/digest/Profile、取消、预算、迟到结果失效、缓存隔离 | 声明业务来源，遵守当前调用的身份与范围 |
| 教室身份与通用属性 | 稳定标识、类型标签、容量用途、未知值的标准含义 | 映射校区/楼栋/教室代码，解释学校字典与缺失字段 |
| 时间与可用性 | 绝对时刻、半开区间、完整覆盖、未知/冲突规则；设备时区显示 | 校历、日期到教学周、作息表、占用协议、源站实际精度 |
| 服务端查询条件 | 有界类型校验、标准语义、原生输入、显式提交 | 提供支持条件、选项、依赖和默认值，验证组合并转换成学校请求 |
| 学校特有条件 | 版本化且有声明的扩展条件容器，未知条件明确拒绝 | 解释条件 id 和枚举值；HTTP `querySetting` 等完全留在脚本内部 |
| 本地结果筛选 | 在已加载范围做文本匹配、排序和精确区间筛选，显示覆盖限制 | 返回足够证据和完整性，不能用不完整结果声称全校无匹配 |
| 占用详情 | 原生详情布局、按需读取、加载/过期/失败状态 | 查询学校明细，归一占用类型、原因与可披露文本，不输出不必要个人字段 |

讨论细化：学校脚本可以自行声明字段 id、标签、类型、选项、默认值和约束，不要求每新增一个学校筛选项都先注册核心标准字段。核心统一表单协议，各校表单内容按实际能力生成。标准语义绑定是可选增强：字段明确绑定“上课座位数下限”等语义后，核心才据此做跨学校操作或本地优化；未绑定字段仍可正常提交给同来源脚本。核心不从标签或字段名猜测含义，也不把学校类型代码当成跨学校枚举。

## 接口选择与后续范围

ADR-082 首片冻结的版本为 `query.controls 2.0`、`params.query.controls 2.0`、`params.grades.list 1.1`、`params.classroom.available 1.2` 和 `classroom.available 1.3`；ADR-083 仅将表单输出和参数继续升至 2.1，保留 2.0/1.0 快照和消费者。没有新增全局 SDK API。以下保留完整讨论范围，其中超出首片的字段和能力仍是候选：

1. **教室属性和证据扩展。** 类型保留来源内的稳定 code 与 label；座位按用途区分 teaching/exam，不静默把旧 `capacity` 改成上课座位数。占用保留可扩展的类型/标签和可选原因；新增精度、推导依据与覆盖范围。缺失与零不同，无记录与实际可进入不同。
2. **查询输入新版本。** 通用日期/绝对时段、校区/楼栋/教室、容量用途与阈值、类型条件有明确语义。声明不支持的条件应拒绝或明确返回未应用，不能悄悄忽略；结果回显实际条件及查询完整性。跨午夜如何拆分及上限需要明确。旧 `start/end` 仍保持原有节次窗口语义。
3. **`query.controls 2.0`。** 已采用核心提供有限控件类型、脚本创建具体业务字段的方案；一张表单最多 32 项，值置于独立的 `filters` 容器，不覆盖身份、来源或宿主控制参数。接收当前条件以加载依赖选项（如校区→楼栋），支持数字/多选输入及约束。依赖变化清除下游选择，显式提交才替换原查询，缓存包含完整条件。学校扩展条件限定类型/大小/声明，不开放 URL、任意请求体或命令透传。旧 1.0 继续按旧参数和含义运行。标准语义绑定留待后续设计，未绑定字段也能正常使用。
4. **按需占用详情能力。** 以来源内教室身份和查询时段为键返回类型与明细，支持有界批量/分页和缺失状态；是否独立命名为 `classroom.occupancy` 待定。直接附加在主查询时也必须有明确的详情级别与预算，不能默认每格取明细。

已有 `intervals[].reason` 可以承载真实纯文本原因，单独改善此字段内容无需新 schema；结构化多原因、属性用途与来源精度才需要新增契约。容量显示也已有 `capacity`，但把学校两种座位数塞入同一字段会丢失用途，不能作为最终模型。

这些变化主要是只读领域契约与展示能力扩展。现有 HTTP、凭据、取消和网络范围端口足以实现样本中的查询，无需新的 raw socket、任意文件访问、公共中继或特权执行接口。浏览器 HAR 录制是开发机工具，不需要放进学校 SDK。

## 筛选交互建议

实施前页面同时拥有原生日期/楼栋、脚本条件里的日期/房间/学校时间，以及结果内的房间文本和设备时间筛选。同名条件容易混淆，且两种时间筛选实际语义不同。

首片的新表单提供统一查询条件入口，标明学校时区；日期、地点、类型、容量、目标时段统一提交，旧包仍使用旧协议。ADR-083 继续移除结果下方重复的文本/时段条件与独立文字详情，将教室属性和原因并入对应行。这里保留的连续时段筛选讨论仍要求完整已知空闲覆盖；节间缺口保持未知，不能用大节端点推导课间可用。当前西电脚本的时段条件按覆盖到的节次判断，表单明确这一限制，不能冒充连续分钟级空闲。

不支持的条件不显示；若源站不能按座位过滤但返回足够容量数据，脚本可以在取回结果后实现该条件，并声明覆盖范围。未提供容量、选项加载失败、尚未选择上级条件分别处理，不能都显示为空下拉框。

默认可以“查找指定时段可用教室”，仍允许查看全部占用与未知记录。若首要用途是浏览全天，则默认不启用可用性过滤、详情按选中教室加载。两者共享同一数据模型，不必维护两套学校请求。

兼容性目标是旧包继续按旧含义运行、新包明确声明所需版本、不支持的字段明确处理；不是用开放 JSON 让每个消费者猜测学校字段。新属性在旧卡片可缺省，新的查询语义与依赖控件需要明确升级；安装更新继续重新批准 digest。

## 验证范围

从结构构造合成数据：两种座位数不同、未知/零容量、未知类型码、多种占用并存、缺时间、缺节次、跨时区/跨午夜、分页截断、详情失败、条件依赖失效。验证实际学校模块→标准结果→原生页面/缓存/AppFunctions；精确区间路径仍须显示楼层和容量。新旧 schema 与脚本包分别回归。真实 HAR 仅用于本地研究，合成测试不代替真实学校验收。
