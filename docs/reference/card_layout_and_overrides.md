# 卡片布局与同名能力覆盖

依据 [ADR-043](../adr/adr_043_card_layout_and_overrides.md)。本轮为客户端首个可运行切片；中继服务、匿名增强权限和论坛/馆藏新模型仍未实现。

## 编辑首页

长按任一卡片即可直接拾起；拖到目标格位停留片刻，卡片会吸附到格子，冲突项即时让位，松手保存。目标可以是空格，主动留下的空位会保留，支持错位摆放。拖到屏幕上下边缘会自动滚动。取消手势或移出布局区域松手会恢复原顺序。卡片没有外围编辑边框、拖动把手或缩放框。

长按或点“编辑布局”后，点卡片可打开尺寸、上/下/左/右逐格移动及向前/向后移动菜单，也支持键盘和辅助功能操作。进入拖动会收起临时展开的详情，拖动期间不能同时修改展示配置。点“完成”恢复业务点击。三档布局适用于所有首页业务卡。常规四列，格间距统一为 12dp；若单格宽高为 w/h，半宽摘要严格为 `(2w + 12) × (2h + 12)`，与四个小入口及内部间距等大。行高按列宽和字号统一确定，不随某张摘要内容变化：

| 档位 | 布局 | 信息量与操作 |
|---|---|---|
| 图标与名称 | 1×1 格（通常一行四个） | 整格为按钮，图标下方显示名称；点击展开 |
| 半宽摘要 | 2×2 格 | 标题、关键值或最新一条摘要；点击展开完整内容 |
| 全宽详情 | 全列宽，至少两行，内容高度向上取整到整格 | 查询表单、详情预览、来源和时间、完整结果及专用控制入口 |

| 业务 | 半宽摘要 | 全宽内容 |
|---|---|---|
| 通知 | 首条标题、来源和日期 | 最多十条预览，全部已加载结果与详情 |
| 课表 | 首条课程、学期/周次/数量 | 周次选择、课程时间地点与列表 |
| 成绩 | 权威 GPA 或首条成绩、学期 | 明确绩点口径的课程列表与详情 |
| 借阅 | 首本书、数量/到期/逾期提醒 | 借阅详情、完整已加载列表 |
| 一卡通 | 余额及账户状态 | 账户信息、交易明细入口 |
| 考试 | 首条考试及时间 | 考场、座位、状态等详细安排 |
| 教室 | 已知空闲数量及日期 | 教学楼/日期筛选、各教室状态；未知不计为空闲 |
| 水电 | 所选表余量、名称/查询时间 | 表具选择、日期窗口和历史读数 |
| 空调 | 已核验温度、开关状态/时间，或未知/失败 | 设备选择、状态和原有确认控制 |
| 通用信息 | 首个字段的值及名称 | 全部字段与表格 |

小尺寸点击后在原位临时展开，点“收起”恢复，不改已保存的尺寸或格位。业务组件持续挂载，拖动、切尺寸和展开保留查询结果及选择。半宽摘要按空间限制行数，完整信息通过展开查看；未加载、需要登录、加载中、失败各有提示。很窄时回到两列，大字号统一提高行高，不缩小文字；屏幕适配不写回格位，主动编辑才保存。

布局按学校与稳定业务 ID 保存。v2 将旧 v1 的紧凑档迁为半宽、常规/展开档迁为全宽，保持顺序；新安装默认半宽。刷新、来源覆盖与包更新不重置用户偏好。编辑态屏蔽业务点击和焦点；保存失败可重试，“主页展示”中的“恢复默认”清除本校偏好。自动回归不代替 Android 真机手势验收。

## 选择主页内容和展示样式

“主页展示”入口始终出现在有可用卡片的首页上，可逐项打开或关闭本校卡片。也可在编辑态的卡片菜单中选择“从主页隐藏”。全部隐藏后仍保留入口与添加提示。隐藏保留顺序、尺寸、样式，恢复后沿用；新提供的卡片默认显示，暂时不可用的卡片保留设置。隐藏只改变首页展示，不等于禁用学校能力或停止会话缓存刷新。隐藏后恢复可能重建业务组件；普通尺寸切换继续保留查询状态。

当前存储为 **v4**：`order`、`sizes`、`hidden`、`presets`、`positions`。格位以 `{column,row}` 保存，列 0–3、行 0–1023；横向坐标从文字起始侧计算，RTL 镜像显示。v1 先按既有规则迁移尺寸，v2/v3 保留尺寸、顺序及已有显隐/样式；没有坐标的旧布局按顺序自动占空格。显式格位先保留，碰撞或未定位项确定性补位。各学校独立保存，保存失败会提示重试。

具体业务样式的扩展入口已预留：客户端 `HomeCardEntry.presets` 登记有限的样式 ID 与本地化名称，业务组件通过 `HomeCardPresentation.presetOf(context)` 读取选择，在原组件和查询状态上展示。尺寸和样式分别保存；`standard` 始终可选。未实现或当前版本不支持的样式回退标准样式，保留用户偏好。存在已实现的额外样式时，卡片编辑菜单才出现“展示样式”。

课表课程预览、考试下一次考试等**具体预设尚未实现**；后续分别接入各卡片。扩展仅属于宿主 UI，不是新的 SDK 能力或 manifest 字段，不能改变数据来源、查询语义和控制确认流程。

## 首页标题

首页顶部显示学校名称与最近一次成功数据更新时间，不再重复显示 elecon 和校园信息面板。SDK 7 脚本可用可选 `manifest.homeTitle` 覆盖顶部标题；`name` 仍是安装包名称。字段为单行纯文本，最多 80 个 Unicode 字符，不接受控制字符或双向控制字符。字段展示在安装确认中，并受包 digest 授权；更新须重新确认。

```json
{ "sdkVersion": 7, "homeTitle": "我的校园" }
```

这只是 manifest 片段，其他必需字段照常提供；已有脚本更新时也需提升包 version 并重新打包。SDK 1–6 不接受该字段，旧宿主拒绝 SDK 7；SDK 7 继承现有 cards/home/actions。

本地脚本学校使用首个仍启用的学校包的标题；后来安装的同校包不自动改名，只有禁用/卸载原包后才重新选择。目录学校使用固定业务优先顺序中的有效基础来源，能力覆盖不接管标题。未指定时显示学校名。顶部时间来自成功数据/缓存的实际完成时间，失败不会刷新旧时间，无数据时显示暂无更新；各卡片仍保留各自时间和过期提示。

## 脚本建议默认形式

SDK 6 可选静态声明（放在 manifest 中）：

```json
{
  "sdkVersion": 6,
  "cards": [
    { "type": "notice", "defaultVariant": "compact" },
    { "type": "schedule", "defaultVariant": "regular" }
  ]
}
```

这是 manifest 片段，仍须保留正常的 id/version/schoolId/network/capabilities 等字段，并实际提供对应能力。`cards` 不替代查询与缓存用的 `home`；不包含 Widget tree、颜色、像素尺寸或事件代码。用户设置优先于建议，建议优先于宿主默认。旧 SDK 1–5 不接受 cards；现有学校包无需为布局功能升级，未声明时用宿主默认。

SDK 6 声明范围保持首版约定：notice、schedule、grades、library 可建议 compact/regular/expanded，其余仅 regular。这些旧建议的含义不变：compact 映射到本地半宽，regular/expanded 映射到本地全宽。客户端所有业务卡均可由用户选择本地三档。主包展示建议由稳定基础来源读取，增强覆盖不接管用户布局。

## 使用同名覆盖

主包和增强包照常导出 `capabilities`，增强包仅实现需要替换或补充的标准入口，无需主包检测增强包。用户检查源码和网络范围并安装后，在“学校脚本”工作台选定能力，再点“使用此来源”。恢复默认来源、禁用或卸载覆盖包会回到原有可用基础来源；原基础包不可用则明确失败，不选择从未选中的陌生包。

更新包保持来源选择，改变输出版本会使旧绑定不可用，需要明确重新选择兼容来源。通知列表/详情、教室发现/查询、水电表具/用量及空调发现/状态/控制按已存在能力组成来源组，防止将一个包的实体 ID 交给另一个包。此版本未提供跨源实体映射。

覆盖只改变宿主调用目标，各包继续独立执行；没有覆盖才用默认来源，执行失败不自动回退或重发。控制操作仍经过原有专用确认。未选中的实现不参与首页预加载。

当前 SDK 1–7 仍是受信学校包，同校 namespace 不是权限隔离；不能把“增强包”名称当作匿名权限保证。本轮没有公共缓存服务，以上操作只提供客户端可选择的数据实现。
