# 论坛与消息系统实施计划

> 更新：2026-11-01。依据 [ADR-051](../adr/adr_051_forum_and_messages_reservation.md)；本轮只预留原生入口，服务接入、额外登录、schema、写操作与推送均未实现。相关通用来源/分页方向见 [platform_evolution](platform_evolution.md)，当前账号边界见 [ADR-044](../adr/adr_044_local_profiles.md)。

## 产品范围与待定事项

论坛提供板块、主题、正文与回复；首个数据切片只读。消息面向回复、提及、站内信等属于明确服务账号的收件内容，与首页学校公告分别呈现。能匿名浏览论坛的服务不强制登录；需登录才可读的服务展示其明确登录要求。未登录、未加载、读取失败与已加载空列表分别表示，未取得未读计数时不画“0”。

来源需在实现前确定：接入学校已有服务，或另行建设 elecon 社区。先确认接口/使用授权、是否允许匿名浏览、登录方式、稳定用户 ID、学校归属、分页、消息/未读能力和会话撤销。自有服务还需独立决定注册/找回/注销、内容审核与举报、反滥用、数据保留和私密消息的访问授权，不复用静态脚本分发后端。

论坛账号可能独立于学校账号。产品入口先解释需要登录哪个服务，待服务选定后提供“登录该服务 / 切换账号 / 退出该服务”；本轮不收集密码、不展示无效登录表单。关联学校身份必须显式授权，不能自动发送学号、学校 cookie 或学校登录凭据。

## 身份、缓存与取消设计（Proposed）

| 对象 | 拟定语义与边界 |
|---|---|
| Profile | 沿用本地独立会话边界，不是远端注册账号；切换时销毁旧导航、草稿视图、请求与临时正文 |
| Service | 稳定服务 ID、受审核源与认证方式；展示名/域名变更不自动改变主体；切校后的可用范围由服务声明与授权确定 |
| Account | 服务给出的稳定 ID；显示名仅作展示，学校用户与论坛用户不靠相同文本合并 |
| Session | 每个 Profile/service/account 独立凭据与执行代际；退出服务取消在途请求、清除该账号敏感缓存及未读状态，不退出学校 |
| Entity | 主题、回复、会话、消息以来源和远端 ID 组合寻址；列表、详情、分页、未读更新绑定同一账号和提供者 |
| Cache | 至少按 Profile、service、account（匿名有独立范围）、学校授权范围及提供者批准 digest 隔离；保留取得时间、原始时间、分页与 stale/partial |

切校不自动把新学校凭据授予论坛。学校绑定服务先停止旧范围请求，重新验证可用性；跨校独立服务也要保留明确服务账号身份。退出一个学校会话与退出独立服务不是同一操作；按服务实际撤销机制处理，不承诺未实现的远端注销。禁用/更新脚本使旧批准 digest 的结果不可读，晚到结果不可进入新账号/来源；当前 SDK namespace 不提供跨脚本凭据隔离。

私信正文、附件、草稿不进入公共缓存、诊断日志或共享首页偏好。持久化是否开启、TTL、附件访问和退出清除策略在账号 ADR 中决定；占位切片无持久化。消息未读状态的本地值不能代替服务确认，显示正文也不应隐式触发标记已读。

## 领域契约准备（Proposed，未注册能力）

论坛与消息各立 schema ADR，不用 `notice.list/detail` 或 `generic.section` 改义实现。下表是设计清单，不是现有 SDK API；选定服务后才确定能力 ID、参数与版本。

| 领域 | 契约需要明确的内容 |
|---|---|
| 板块与主题列表 | 板块/主题稳定 ID、账号可读范围、标题、作者显示身份、置顶/锁定/删除/审核状态、排序、过滤和游标分页 |
| 主题与回复 | 同源主题/回复 ID、作者、楼层或位置（不猜补缺号）、引用/编辑/删除状态、创建/更新时间、富正文和附件 |
| 收件列表与详情 | 来源、账号、消息稳定 ID、类别、发送方、会话/主题引用、收到时间、可选阅读时间及分页；缺失阅读状态表示未知 |
| 未读与同步 | 服务确认的计数与统计范围、同步游标、去重、已删除/撤回、断线补拉、过期游标和局部失败；不由当前页条数猜总数 |
| 错误与权限 | 登录过期、缺权限、不存在/已删除、限流、离线和服务不支持分别表达；不可读正文不得被旧账号缓存补回 |

时间区分 RFC3339 时刻与日历日，缺失值不伪造零/false，分页保存 next cursor 与完整性。正文由宿主有界渲染，链接/附件保留来源并受实际账号和网络授权约束，不执行文章脚本，不把鉴权 URL 交给通用 UI 任意请求。来源变更后不能拿旧 ID 向新提供者查详情。

发帖/回复、发送消息、标记已读、删除等均有副作用，安排在后续独立切片。需明确每个操作的输入、幂等支持、取消、发送中、已确认、结果未知与对账方式；禁自动重发或切源重试。受信脚本传输沿 ADR-046 的通用请求，不重新引入已废除的 action 字段；不在本轮先实现通用写操作框架。

## 按依赖实施

| 切片 | 内容与位置 | 验收与回滚 |
|---|---|---|
| F0 本轮入口 | `ui/shell/main_shell.dart` 四导航、`ui/community/` 本地占位页、zh/en 文案 | 页面状态明确、无额外登录/业务请求；删除导航即可回滚，无数据迁移 |
| F1 来源与账号决策 | 确认目标服务；起草认证/凭据/会话 ADR，说明与学校、Profile、脚本权限的实际关系 | 合成账号的登录过期、切换、退出、重启、禁用与晚到结果；安全实现人工审阅；尚未进入实现 |
| F2 论坛只读 | 领域 schema/registry/生成物/decoder、板块/主题/回复、同源详情、固定原生分页与正文 | 合成 fixture → 实际接入代码 → 标准输出 → 页面；loading/error/empty/stale/partial、撤回、权限与分页；保留入口可单独停用提供者 |
| F3 消息只读 | 账号收件箱/详情与可选未读数；先前台显式刷新，阅读不发标记已读 | 未知计数、重复/乱序、删除、过期与跨账号隔离；无服务能力时明确不支持，回滚清该账号消息缓存 |
| F4 明确写操作 | 登录后发帖/回复、发消息与阅读状态操作分别设计，不强制一次交付 | 用户触发、服务幂等键（若支持）、网络失败未知态、取消与对账、禁止自动重试；实际账号验收单独授权 |
| F5 后台与推送 | 服务确有支持且用户授权后再设计通知权限、设备 token、预算、断线/前后台去重与撤销 | 推送正文暴露策略、退出解绑、Profile 切换、离线补拉与平台真机；不把后台能力写进当前 manifest |

F1 在 F2/F3 之前；F2 与 F3 可按目标服务分步交付。消息无需等待完整通用增强平台，但必须具备自己的账号与同源实体边界。匿名论坛不能被描述成现有的低权限脚本沙箱；涉及宿主新权限的设计先另立 ADR。

## 本轮交付与剩余验收

本轮交付是原生导航、两页可辨识占位状态与本计划。尚无服务选择、账号系统、forum/message 契约、登录实现、真实内容、未读状态、发帖/发送、轮询、推送或后端部署。后续实施不能仅因为本文件出现领域名，就将其加入学校包 manifest。

自动 widget 回归使用合成学校快照，覆盖入口切换、窄屏/两倍字号/深浅色/zh-en，确认占位页不调用业务能力。已有 Profile 设置与启动回归也需保持。真实学校/服务账号、平台真机与安全人工签收分别记录，不用占位页和自动测试代替。
