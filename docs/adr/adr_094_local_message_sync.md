# ADR-094 · 用户启用的本地只读消息同步与通知

- 日期：2026-11-05
- 状态：**Proposed**。未接受、未实现；当前消息能力仍遵守 ADR-061 的前台限制，不新增可用 manifest 字段或后台放行例外。
- 承接：ADR-061、063、066、080；证据入口为[校园体验研究](../research/campus_experience_android_2026_11_05.md)。

## 范围与选择

提议由用户为特定来源和消息账号启用设备本地只读同步，再按独立通知选择提示新内容。设备直接查询已授权学校端点；既有公网静态分发服务不接收凭据、IM token、消息正文或轮询学生账号。同步成功、通知权限与系统实际展示分别报告。

首片不接 FCM 或厂商推送：现有学习通脚本只有用户会话访问路径，没有上游环信应用的管理权、回调或推送发送授权。安装 elecon 自有推送 SDK 不会取得官方客户端的消息。将来接通道需有合法上游事件、应用身份/证书、受信发送端和独立撤销设计；不能凭空接入或以公网代持凭据补足。

本地周期同步是尽力更新，不承诺即时到达或后台常驻。平台不能执行、用户强制停止、设备未解锁或认证需要交互时如实等待，不改系统设置、不索要忽略电池优化作为默认前置，也不借前台服务维持无限连接。

## 候选接口与执行授权

不把旧 `messages.conversations/history` 的普通 `interactive:false` 重新解释成后台权限。建议新 SDK 增加有明确授权与预算的只读 `messages.sync@1.0` 入口，旧能力的前台门保持不变。候选 manifest 只声明支持这一受限同步入口；安装授权说明后台取数能力，**实际运行仍需用户另行启用计划**。接受后才分配 SDK 版本并同步 schema/SDK/准入/手册。

| 候选输入/输出 | 具体语义 |
|---|---|
| 输入 `accountId` | 由宿主已验证账号绑定生成，不能由后台任务切换到其他账号。包、Profile、学校、serviceId 和批准 digest 由执行上下文固定。 |
| 输入 `checkpoint?` | 该绑定上次持久提交的增量游标，最多 4096 字节；脚本按学校协议解释，宿主不猜测消息 ID 的数值或时间顺序。新计划不复用其他账号/来源的游标。 |
| 输入 `phase` | `baseline/delta`；首次授权、重新绑定或游标失效后进入 baseline。不能因重新登录重置一个布尔值便把历史消息全当新增。 |
| 输入 `limit` | 宿主设定本次有界返回条数与分页预算，脚本可少返回；不能自行无限扫群/历史。用户选择的会话范围作为计划快照，未选会话不能扩入该计划。 |
| 输出身份 | 必须回传相同 `serviceId/accountId`；每组会话含 `conversationKind` 和 `conversationId`，复用当前消息标准内容字段及稳定消息 ID，群/私聊同名 ID 仍隔离。 |
| 输出分页 | `nextCheckpoint?`、`hasMore`、`coverage: complete/partial` 和源站取数时间；缺失/部分失败不能伪造完整。checkpoint 只在对应数据成功持久提交后推进。 |
| 输出变化 | 普通消息及撤回 ID 墓碑；不输出发送动作、已读副作用或任意 URL。命令/协议回执继续作为现有标准的惰性内容，不触发自动操作。 |

服务无法给出可靠的增量界限、稳定身份或“历史/新增”区别时，可以只做静默有限归档并显示覆盖不足；不得启用“新消息通知”并猜测。使用 fetchedAt 或群资料更新时间推断新消息不成立。协议不能支持本入口的旧包继续使用前台历史页，无后台自动适配。

宿主调用入口带不可由普通脚本参数伪造的 `backgroundMessageSync` 执行来源及计划租约；只有该入口可经新通道执行。后台不提供输入、浏览器、扫码、位置、红外、文件、发送消息或任意嵌套命令端口；学校认证需要输入时返回 `waitingForInteraction`。已存在的受限 HTTP/WSS 仍遵守批准 origin、DNS/TLS、隧道、取消和资源预算，依赖隧道但未就绪时不得直连回退。

“只读”是已审阅入口的业务约定与宿主可执行能力限制，不意味着宿主能从任意 HTTP 请求自动判断上游副作用；受信学校脚本仍需实质审阅，namespace 不成为包间最小权限沙箱。不得通过删除全部社区前台校验来落实这一提案。

## 计划、身份与受保护存储

计划 v1 由宿主托管：随机计划 ID、Profile/学校、包 ID/digest、serviceId/accountId、可跨重启核验的身份代际、会话范围、周期/允许时段/时区、网络条件、通知隐私选择、启用时间、最近尝试/成功时间及标准状态。运行记录含独立 runId、源站 checkpoint、当前 phase、预算使用与净化错误分类，不含凭据、正文或原始响应。

Android 调度信息只存随机 planId；正文、账号、游标和计划配置留在现有 H/S 受保护存储。M 档不因后台同步写明文；首片不提供进程退出后的持久计划，界面明确“不支持持久后台同步”。H 档在锁屏/重启后无法无交互解密时等待用户解锁，不降低保护等级或从系统日志恢复凭据。

每次运行在领取、读取绑定、每次出网和提交时复核持久身份代际及批准 digest。单计划至多一项在途执行，同一来源/账号的前台与后台归档写入串行化，不能各用旧数据库快照覆盖另一方。持久领取租约记录运行所有权与过期时间，进程退出后释放/重取只允许只读查询，不会重放发送命令。

撤销计划、账号退出/重新登录、来源禁用/删除/更新、Profile 删除都先撤销持久代际、取消在途运行与调度，再清除本地路由和相应通知；晚到结果不得写入新账号。包更新后计划暂停并要求用户批准新 digest 后重新启用，不静默把旧计划换到新代码。切学校/Profile 停止当前后台执行并暂停其调度；切回也不以另一身份替代绑定。持久撤销失败时不启动新身份任务，下一次恢复必须先完成失效记录。

## 有界增量与通知去重

建议首片周期默认 30 分钟，可选值不小于 15 分钟；每次运行最多 30 秒、5 页、200 个消息变化和 10 个会话范围请求，全设备最多一个后台脚本运行。数值是待测的首片预算，不是吞吐或电量结论。到期仍有页保留 `partial` 和已持久游标，下个允许窗口继续，不紧密循环补历史。认证等待和永久拒绝不指数重试；暂时网络失败最多两次有界退避，超出本次窗口等待下一周期。

Android WorkManager 的周期最短 15 分钟，具体时机受约束和系统优化影响，可能延迟或跳过；首片不申请精确闹钟权限。[Android 周期工作说明](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)

baseline 各页只导入/去重/合并墓碑，直到源站确认基线边界并持久提交，全部静默。后续 delta 的消息与通知候选在同一归档事务中提交，候选键由绑定代际、会话类型/ID、消息 ID 与事件种类构成。仅新增、可显示、未撤回的 incoming 内容可通知；旧页重叠、重复 ID、outgoing、协议回执和命令不再产生通知。缺 direction 或新增证据时保持静默。

归档提交成功后才尝试系统通知。发出前先持久记录候选的 `dispatchAttempted` 和尝试 ID，再以稳定 tag/id 及 `setOnlyAlertOnce(true)` 提交通知；提交成功只表示 API 已受理，不等于用户已看到。进程在调用前后退出时保留 `deliveryUnknown`，不重新提示该候选，因此可能漏一次通知但不会把历史重新连发。已提交/未知/抑制状态持久保存；通知权限被拒时标记抑制而非排成长队，随后开权限不补发历史。撤回墓碑先到也阻止后续旧正文出现；已显示消息撤回时取消/更新对应通知。候选集合有大小与保留上限，源站成功但归档失败不推进游标、不展示通知，下次读取仍按消息 ID 去重。

这些规则不能提供端到端 exactly-once；系统可能未显示、聚合或保留旧通知。页面不凭通知数推断服务未读数，不自动提交已读状态，不提供后台发送或通知快捷回复。

## 通知与页面恢复

启用同步与允许通知是两项选择。Android 13/API33 及以上的一般通知需请求 `POST_NOTIFICATIONS`；用户拒绝时同步可按已启用计划继续，界面显示“通知未获允许”。[Android 通知运行时权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)

默认通知仅显示“elecon 有新消息”，不含学校、账号、群名或正文。用户可为当前绑定明确选择显示会话名/有界文本摘要，并看到 Launcher/系统可能缓存内容的说明。锁屏使用私密可见性及无内容 publicVersion，不能承诺撤回截图或系统已缓存的内容。通知展示隐私不改变受保护消息库权限。

点击使用显式、immutable 的 PendingIntent，仅携带随机路由 token；token 在宿主保护层映射到原 Profile、学校、来源 digest、账号和会话，正文/凭据不进入 Intent extras。恢复经过正常解锁、Profile/学校及来源校验；绑定已撤销时显示不可用入口，不跳到当前其他账号的同名群。通知 receiver 不导出，不能从外部填入任意能力/参数；不附发消息、标已读或执行活动的 action。

## 版本、依赖与验证

接受后新增 SDK 与 `messages.sync/params.messages.sync@1.0`，不修改 `messages.history@1.1` 的前台行为。归档存储独立升版，增加 checkpoint/phase、持久身份代际、领取租约和通知候选表；事务与容量策略必须经过重启/并发迁移测试。旧存储按旧模型读取，升级首次基线静默；旧宿主拒绝新包，回滚停止新计划、撤销通知并保留可解释的暂停记录。

拟使用官方 AndroidX WorkManager（AndroidX，Apache-2.0）及原生 NotificationManager 桥；接受实施时固定版本、记录官方下载来源和许可证并验证原生构建，不预先添加依赖。[WorkManager 上游源码与许可](https://github.com/androidx/androidx/blob/androidx-main/work/work-runtime/src/main/java/androidx/work/WorkManager.kt) 现有 sqlite3/受保护存储许可与来源继续沿 ADR-061。FCM/厂商 SDK、服务端和上游合作均为另行设计，不在本提案引入。

合成验收覆盖首次历史静默、增量/回退/循环游标、部分覆盖、重复/乱序/撤回先到、群私聊同 ID、存储失败及事务恢复、并发前台归档、通知展示前后崩溃、权限拒绝/后续允许、来源更新与跨重启撤销、错误身份、M/H 档不可读、取消及后台认证等待。原生测试覆盖 Doze、强制停止、重启/未解锁、系统通知权限、真实点击恢复和最终路由失效。

关闭条件还包括对应学校的合法增量协议证据、有限真实账号同步、真实通知投递及核心/凭据/网络人工实质审阅。当前仅完成提案；现有合成聊天测试、系统能力声明与源码状态都不能替代这些验收。
