# ADR-053 已授权来源升级与独立服务取消

- **Decision**：Accepted（2026-11-01，所有者要求修复学校登录、课表消失及独立睿思/社区账号，不在学校导入中分发学习通）。
- **Landing**：注册表恢复、单次取消与社区包导入调整已实现；真机观察与自动回归分别记录于[实施计划](../planning/trusted_scripts.md)。
- **承接**：ADR-034/035/043/048/052，不改变 SDK、输出 schema 或网络权限。

## 已授权基础来源的契约升级

注册表旧 v2 把 schemaVersion 永久钉在首次安装时。学校包经内容确认从课表 1.0 升至 1.1 后，绑定未更新，导致 provider 消失。基础包身份仍必须稳定；批准同一基础包的新源码也批准其明确声明且宿主支持的能力版本。安装更新时同步其基础绑定的版本，不改变 baseId、覆盖来源选择、学校、enabled 或已批准 digest。

注册表 v3 沿用 entries/bindings 结构，明确上述含义。读取 v2 时，仅对存在、无需旧路线更新、同校、同 schema 且仍声明该能力的已授权基础包修复版本；缺失能力、缺失包、跨校绑定继续不可执行。覆盖包不因升级获得新来源选择；其契约必须与当前基础绑定精确匹配，不兼容时仍不可用，不自动回退或重试。v1 先按旧实际来源迁移，再采用 v3。下一次注册表写入保存 v3；不更改包源码或授权 digest。旧客户端不识别 v3，回滚应保留注册表备份或由用户重新导入，不直接修改旧授权内容。

同一身份的查询缓存继续绑定具体包 digest，新版本重新取数；不能把旧契约缓存直接冒充新数据。来源恢复后按现有 preload 策略刷新，不重置用户布局。

## 独立服务调用

睿思和社区包账号按现有服务记录保存。登录、退出或失败仅影响自身服务；学校登录和课表不能以论坛会话成功为前提。页面为其调用持有独立取消句柄：离页/关闭该登录只撤销该调用及其 HTTP/WebSocket，不提升整个学校执行代际、不取消其他排队任务。学校、Profile、授权来源变更及全局退出仍撤销全部调用；每次执行仍校验原始身份、代际、批准 digest 与启用状态。

学习通作为第三方社区包由用户自行构建/获得后通过通用文件导入；移除客户端内置产物、导入按钮及推荐文案。协议源码及仅测试用编译夹具不作为客户端分发资产。

## 认证兼容修复

学校包 0.18.1 限定 Cookie 的站点根范围（学校脚本内明确列出的服务站点，非宿主通用 PSL）；旧会话内公共后缀 Cookie 不再恢复或发出，新响应同样拒收。学校与社区网页登录遇暂态导航错误时在脚本侧等待，避免页内计时器尚未运行就耗尽所有轮次。保持原站认证、身份核验、TLS 和现有网络范围，不以存在任意 Cookie 作为登录证据。

## 验证

覆盖从旧绑定打开、批准基础包升级、失效覆盖包、跨校/篡改 digest 拒绝、写入失败原子性与重启；实际首页在旧绑定恢复后重新显示课表。覆盖服务失败/取消后学校凭据、查询及缓存不受影响，迟到服务写入被拒绝。设备调试仅记录脱敏阶段和结果，不提交账号、凭据、课表正文或设备标识。自动回归不替代真实服务验收及人工安全审阅。
