# ADR-099 · 有界并行查询与渐进会话目录

- 日期：2026-11-10
- 状态：Accepted（所有者授权形成完整预案并无人值守实施；实现、学校验收及人工核心审阅分别记录）
- 承接：ADR-038、046、061、081、095、097、098；替代 ADR-097 的全局单执行队列限制。

## 问题与目标

首页预加载逐项等待，所有受信脚本又共用单一队列。慢查询会阻挡无关卡片和具有端到端期限的 AppFunctions。学习通 0.6.0 将目录、群成员、名称和头像全部放在一次调用中，可选请求超过宿主 40 次硬预算后，已取得的目录也无法返回。合成真实 QuickJS 对照可复现该回归；设备出现相同通用错误，但正式版日志不足以断言该次设备失败的具体错误码。

核心提供身份与来源绑定、可取消调度、资源计量、标准会话数据及增量合并。学校脚本负责认证证据、请求依赖、协议、批量接口、成员采样、名称生成和补全缓存策略。任何聊天后端都可只实现目录；头像、最近消息、排序和补全入口全部可选。核心不得包含学习通 URL、环信群成员规则或按学校名称分支。

## 执行与凭据协调

SDK20 在能力声明中增加可选 `concurrency.credentials`，为本次调用可能访问的完整凭据地址列表，每项为明确的 namespace/key；空列表表示不访问脚本凭据。宿主在启动 QuickJS 前一次取得全部地址的独占运行权，共用地址跨包串行，不同地址可并行，不在运行中升级锁。桥接器拒绝声明外的凭据读写及整库枚举，报 `credential_scope_mismatch`，不自动重跑。它是受信脚本为避免并发覆盖承担的执行约束，不是包间最小权限沙箱；同校脚本仍可显式声明共享地址。

没有该声明的能力、SDK1–19、显式登录/退出、命令、交互账户管理和注册处理器保持学校范围独占。旧调用与新调用也互斥，不能因包不同绕过旧脚本的共享凭据保护。学校迁移必须列出认证恢复可能触及的母/子会话；无法确定时保留独占。相同会话中的业务读取先保持串行，不能把远端会话写入的安全性归因于本地单线程。后续若需同会话并行，另实施学校认证准备及协议允许的只读票据复用，不用不透明 Cookie JSON 的后写覆盖冒充合并。

所有引擎仍通过同一宿主存储所有者读写，H/S 后端串行持久化；消息归档沿用同库串行事务。不得创建多个整库凭据副本后回写。显式身份变更维持先清业务缓存、持久成功后登录的顺序，撤销旧运行与排队任务；来源 digest、身份及数据代际在启动与发布前复核。

## 调度与首页

进程内最多同时运行 3 个受信 QuickJS 调用，含等待网络的引擎；单个脚本引擎仍受原 CPU、内存、宿主调用和输出限制。静默首页预加载同时最多 1 个，给主动页面与系统查询留余量。队列有界，用户请求优先于预加载；同一凭据的早到任务形成顺序屏障，避免独占任务饥饿。等待取消立即完成，不必等前方任务退出；运行中的取消仍走原有网络关闭和迟到失效。

首页先读缓存，再收集已声明且需要更新的预加载，交给有界调度器；每项独立完成、更新缓存及通知，不等待整批成功。重复刷新合并当前批次。相同身份/数据代际、批准 digest、能力、规范化参数、语言和交互模式的普通只读在途查询可共用一次执行；消费者分别取消，最后一个消费者离开才取消底层工作。账号、命令、二维码及注册处理器不合并，交互端口不同的调用不合并。不同来源不得合并。

AppFunctions 保留当前 28 秒端到端时限，排队时间计入；超时撤销所属消费者，不影响其他消费者。首页刷新不改变旧快照的实际取得时间；失败保留旧值并按既有状态显示。

## 网络和预算

全局 HTTP 在途上限为 8，单 origin 默认 2；每次调用本地上限仍为 4。新宿主的全局等待有界且可取消，排队不占网络连接；网络名额按实际 hop 取得并释放，跳转重新验证网络策略。旧 SDK 本地超并发报错语义保持兼容。HTTP、WebSocket、长期网页及未来持久任务的生命周期不混为一个无限短请求预算。

保留现有单次运行 20/40 次桥接请求、传输 40 个实际 hop、单响应 8 MiB、总响应 16 MiB及超时硬限制。SDK20 增加 `ctx.budget.remaining()` / `elecon.budget.remaining()`，返回本次剩余桥接请求数与传输剩余 hop 数的较小值；这是观察值，不是预留凭证。脚本必须在创建并发任务前分配有限额度，并为认证与重定向留余量。硬限制触发仍中止；不能吞掉致命超限后继续执行。

会话页面一次目录及其自动补全共用宿主过程预算，最多 80 个 HTTP hop；页面自动补全至多 8 批，每批至多 8 个实体。另设同来源滚动窗口预算，避免重新进入页面或刷新制造无限过程。可选补全额度不足直接停止，保留已取得的目录；不把缺头像或无排序信息当失败。调度器与过程预算无权扩大安装包的网络范围。

## 任意聊天后端的目录及补全

新增可选标准能力 `messages.enrich` 1.0：输入为 accountId 与 1–8 个 conversationId/conversationKind；输出携带 serviceId、accountId、fetchedAt 和 0–8 个稀疏实体更新。只允许更新 title、avatarImages、hasContent、lastMessageAt，不更新发送授权、不新增或删除目录实体。缺字段保留现值，`avatarImages: []` 明确清空；缺失排序信息始终未知，不填 0、false 或本地时间。没有该能力的后端只进行目录/历史查询。

宿主发起补全前保存当前目录修订，在同库合并队列取得运行权后再次核验修订；新目录、切账号、退出、来源更新和撤销使旧补全失效。补全只按已请求且仍在当前目录的稳定实体合并，不能创造陌生会话。目录 coverage 仍只表示目录完整性；补全不改写目录 fetchedAt/coverage。已有历史取得的内容证据继续保留。

无头像显示群/联系人默认图标；无最近消息证据不显示时间、不推断空会话或未读。无排序证据时稳定保留后端目录顺序；有证据时沿用内容优先、最新源站消息时间优先及稳定并列顺序。新后端无需实现学习通的成员拼图、群名推导或排序查询。

原生页面先展示目录，再让出 UI 一帧后按当前列表顺序分批补全。页面离开、进入历史、后台或开始新目录刷新立即撤销旧补全；补全不会阻塞打开会话或发送。可选普通网络失败静默保留目录，认证失效、撤销、存储故障及硬限制按原分类处理。历史正文仍按需请求，不扫描全部会话历史来制造排序信息。

## 学习通迁移

增强包升 SDK20 与 0.7.0，基础包升 SDK20 与 0.33.0，均需重新批准 digest。学习通目录入口只取得群/联系人及有界批量群名，不逐群取成员或头像。补全入口使用已有独立实现协议，批量选择至多 8 个实体；每次额外成员请求与图片都服从共享的可选预算，超过额度便省略，后续刷新可再尝试。不在核心缓存学校协议实体。

基础包按实际认证读写声明地址，公共查询声明空地址，其余保守声明全部可能访问的母/子会话。共享会话仍串行，但公共查询、独立服务和增强包不再相互阻挡。SDK1–19 保留原调用与 schema 版本，旧客户端拒绝 SDK20。没有新增安装网络来源、依赖或公共中继。

## 验证及回滚

验证 3 引擎与 8 HTTP 上限、单域名限额、取消释放、队列容量与独占公平；跨包相同凭据互斥、不同凭据并行、旧 SDK 互斥、漏声明拒绝；同请求合并及分别取消；首页慢任务不阻挡无关卡片和 AppFunctions。真实 QuickJS 使用生产预算验证大目录优先成功。

通用后端夹具覆盖无头像、无排序、无补全入口、空补全、稀疏补全、重复/陌生 ID、相同 ID 不同会话类型、目录更新与迟到补全、失败保留目录及显式清头像。学校测试通过真实模块与打包产物，不能只断言小于 256 次请求。

ADB 在现有设备上验证目录首屏、补全不阻塞交互、离页/后台取消及首页刷新；不进行消息发送、签到或设备控制。记录自动测试、构建、设备观察与人工审阅各自范围，不将设备通用错误等同于已取得底层原因。资源参数是首轮配置，不伪造速度或节能收益。

回滚将调度器并发降至 1、停止新补全入口；保留存储恢复和旧 schema 支持。新 SDK 包不能在旧客户端执行，更新需明确提示。实现进度、真实学校验收和人工核心/凭据/网络审阅统一记录在实施计划。
