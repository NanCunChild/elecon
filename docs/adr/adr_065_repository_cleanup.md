# ADR-065 · 开放脚本主线的仓库整理与旧测试隔离

- 日期：2026-11-02
- 状态：Accepted（所有者授权整体整理、必要破坏性重构、不要求数据迁移或旧脚本兼容）
- 承接：ADR-034、041、046、062；不改变包授权、身份、网络或凭据边界。

## 问题与决策

当前开发入口已转向受信学校源码，但部分旧研究、接入模板和测试仍混在活动目录中。它们会使贡献者误以为应继续扩展 V1 无凭据 DSL，或把早期平台探针的未实现结论当成现状。

将已被现行决策替代的文档正文归档至 `docs/archived/2026-11-02/`，保留原路径跳转、历史批准事实及证据限制。当前功能边界统一由 [核心与脚本边界](../reference/core_script_boundaries.md)解释；架构、ADR、实施记录仍各自承担决策与验收状态，边界文档不另建一份进度账。

V1 declarative/imperative 接入模板与 canary 不再作为新学校模板，迁至 `tests/fixtures/legacy-adapters/` 仅供合成回归。`adapters/_template/trusted/` 是现行模板。纯 V1 客户端测试归入 `client/test/legacy/`，修复导入与测试调用，继续被全量测试发现；共享凭据、网络、领域契约与受信脚本测试不因年代而删除。服务端 smoke 保持发现机制和原有断言。

本轮检查发现 V1 loader/Broker/runtime 仍由 bootstrap、会话和服务端消费，因此暂保留运行代码与保护。这里没有长期兼容承诺：未来可依本次授权按可审阅切片退役，但须同时移除活跃入口、发布工具和对应测试，而不能只删安全门。本轮不更改线上数据，不要求迁移旧安装。

## 构建与边界

Android 默认 `fvm flutter build apk` 必须构建请求的全部 ABI，不能用静默省略 ARMv7 或隧道库换取成功。Hermes 使用与 Android Gradle 一致的 NDK；构建前一次报告缺失 Rust 目标，准备步骤明确安装所需目标，CI/release 同步。JDK 原生调用警告在 Gradle 启动配置中修复，不屏蔽编译诊断。包依赖版本不为消除升级提示而无条件升级。

## 验证与回滚

检查归档清单、相对链接、活动入口、移动前后文件与回归断言；运行受影响的服务端 smoke、客户端测试及静态分析。构建验证使用未附加 ABI 参数的 `fvm flutter build apk`，核对 APK 内三种 ABI 的 Hermes 库与许可资产。授权设备用于安装、启动与原生设置交互，真实学校账号、远程控制、网关登录是否验证分别记录，不从启动成功推断。

按文档、测试隔离、构建修复分别提交，可按提交回滚。本次没有新增学校脚本 API 或业务 schema，没有凭据数据迁移。自动检查、设备冒烟与人工核心/网络审阅分别记录；仍须人工实质审阅后合并。
