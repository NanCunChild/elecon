# ADR-062 · APPTunnel 基座选择与核心连接边界

- 日期：2026-11-02
- 状态：Accepted（所有者授权研究 VPN 基座并实现核心选择）；具体基座的原生集成另行验证，不以选择入口代表已经连通。
- 承接：ADR-034、041、044；旧 ADR-003/032 和 Probe-002 只作为历史材料。

## 范围

VPN 在本决策中仅指 APPTunnel：elecon 自己的请求通过应用内 TCP 隧道，不创建系统 VPN/TUN、不更改全局路由、不代理其他应用、不加载脚本提供的原生模块。核心按当前 Profile/学校保存明确选择，默认直连；选中的基座失效、缺失、未编入或设置损坏时停止请求，不能自动回落直连。

核心登记可用基座及只读名称/可用性，UI 选择稳定基座 ID；学校脚本不指定任意插件路径、代理 URL 或隧道句柄。设置只保存非密 ID，认证材料仍需当前 Profile/学校的受保护存储；首片不增加学校脚本权限或接收明文隧道凭证的 UI。

## 接入

受信源码 HTTP/WSS 共用本次执行的 APPTunnel 会话。基座只提供解析和指定地址的 TCP 连接，HTTP、目标 SNI/证书验证、原始 origin/IP 授权、重定向、预算仍由现有宿主管理。校内 DNS 必须来自所选基座，不偷偷使用公网 DNS；返回的地址仍经过包的 IP/CIDR 限制。选择在一次执行内固定，不根据失败自动切基座或重发命令。

切换设置、学校或 Profile、退出及取消立即撤销在途连接；晚到的解析/拨号/基座初始化关闭且不得继续请求。原生 WebView 尚无同等的逐会话接线，选择 APPTunnel 时其浏览器调用明确报不可用，不能悄悄直连。V1 业务/认证也不能绕开已选隧道；其独立支持待实施。

## 基座研究与迁移

以 [Hermes-Atrust](https://github.com/ncc-devlab/Hermes-Atrust/tree/271a547d73c3839365a1995d1a6d72ed915e1458) 为候选，固定检查提交 `271a547d73c3839365a1995d1a6d72ed915e1458`：仓库有 MIT LICENSE，`atrust-client` 提供 TCP dial/shutdown，属于应用内字节流；没有现成移动端 FFI 桥，`TlsPolicy` 仍只有 Verify 与 DangerousAcceptInvalidCertificates，不能把旧探针的 `--insecure-tls` 当生产方案。本轮只读取源码，不引入 Rust 或 GPL 依赖；本地 Hermes-aTrust-Server 是对端服务端，不是客户端基座。

首片登记 Hermes 为未接入候选；用户可以保存其选择，但页面明确提示此构建尚不可连接，网络调用停止。编译期注入的已实现基座通过同一接口选择。真正集成前需完成：移动端受控 Socket/UDS 桥、节点证书/公钥信任与轮换、当前身份的认证材料交接与清除、平台构建和真机。Dart 侧 HTTPS 需要显式 SecureSocket 升级，不能沿用旧 ADR 对 connectionFactory 自动 TLS 的假设。

## 验证与回滚

合成基座通过真实本机 HTTP/TLS/WSS 测试解析/拨号、原目标证书校验、拒绝越界、无直连回落、取消及晚到连接销毁；设置覆盖持久化失败、损坏、Profile/学校隔离与中英文页面。没有真实网关登录、真实学校请求或系统 VPN 操作。恢复直连需用户明确选择；核心/网络实现须人工实质审阅后合并。
