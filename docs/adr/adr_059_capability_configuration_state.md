# ADR-059 · 能力待完善信息状态

- 日期：2026-11-02
- 状态：Accepted（用户授权实施；核心实现仍需人工实质审阅后合并）
- 承接：ADR-038、ADR-046、ADR-056

## 问题与决定

缺少用户尚未填写的设备、房间或业务资料，不等于请求失败，也不等于没有结果。受信脚本通过固定错误码 `configuration_required` 表达这类前置条件，宿主归一为 `CapabilityFailureKind.configuration`。网络、认证、解析错误不得映射为该状态；不返回伪造空集合。SDK 错误词表增加此码，现有数据 schema 不重解释，旧客户端不认识时保持失败关闭。

宿主以当前 Profile 的 H/S/M 存储保存有界的待配置标记，绑定学校、包 digest、能力、规范化查询参数；它不是凭据或业务成功缓存，脚本不能寻址。未配置状态可供所有能力复用。普通自动刷新、整体强制刷新与非交互调用跳过已标记的查询，不启动 JS、不弹表单、不发网络；首次尚未知状态可执行脚本本地前置检查。单卡明确的交互操作可以重试或完善信息。相同能力交互成功清除该能力标记，以支持 `configure:true` 完成配置后恢复默认查询。失败不清除标记；更换来源、升级 digest、切换身份和退出不能复用旧标记。待配置不延长业务缓存的时效。

空调实现先检查已绑定设备：缺绑定且没有显式 `configure:true` 时立即返回固定码；用户选择「完善信息」才请求原生表单。已有绑定仍按源站请求/解析结果区分失败。不将填写了错误设备号的失败显示为尚未填写。

## 迁移与验证

既有客户端内部失败枚举添加成员，穷尽分支同步更新。学校包更新版本；未升级包仍走旧行为，不按自由文本推断配置状态。旧 V1 运行链不新增学校协议。

合成回归覆盖：第一次缺配、后续/force 刷新无调用、显式配置成功恢复、错误请求不被误标记、digest/身份/参数隔离和持久恢复；组件验证待配置与请求失败文案不同。自动测试不代替真实学校验收或人工安全签收。
