# ADR-044 本地 Profiles 与独立会话

- **Decision**：Accepted（2026-11-01，所有者本轮要求多用户独立选脚本与设置行）。
- **Landing**：已实现；本轮相关 417 项自动回归与 Android Debug 构建通过，真机与人工审阅未完成。
- **安全签收**：待人工核心/凭据审阅和平台真机。

每个 Profile 拥有独立 SessionController、CredentialStore、H/S/M 存储选择、脚本安装授权/来源绑定及业务缓存。共享代码、学校目录和应用主题，不共享凭据、安装授权或运行队列。namespace 仍只在同一 Profile/学校内寻址，不是增强包权限沙箱。用户界面只见已有非密会话元数据；Profile 名称是本地标签，不猜测学号或用户名。

新增 `profiles.json` v1 仅保存随机稳定 ID、显示名称与当前 Profile ID。迁移时把旧根目录原位归属 `default` Profile，不复制或重新加密旧凭据；新 Profile 使用 `profiles/<随机ID>/` 下独立 BlobStore。原有 H/S 密文和独立 DEK 机制保留，硬件 KEK 可共享平台密钥但不共享 DEK；内存档仍只在本次进程内存活。损坏索引报错而不自动把旧库授予新用户；索引写失败不切换或新增。没有持久化提供者时使用会话内 Profiles。

切换前撤销旧会话的执行代际并等待凭据持久化，关闭旧界面及认证租约。每个 Profile 的 MaterialApp/Navigator 子树重建，防止页面/临时输入/业务快照跨用户存活。旧调用始终绑定旧 store，迟到结果不能进入新 Profile。切换不是退出，原用户凭据保留；退出只清当前 Profile 当前学校。

设置的账户区域每个 Profile 一行：本地标签、所选登录脚本（缺省显示学校/未选择）与状态，保护状态只用带 tooltip/语义标签的图标；点击打开操作详情，支持添加新 Profile、激活、登录、退出和重新选择学校/脚本。新 Profile 空白启动，重新走安装授权。选校页也可返回已有 Profile，避免新建后无路返回。首页布局继续按学校保存（非密展示偏好），业务缓存按 Profile 隔离。

验证旧目录迁移/重启、同校不同用户凭据与缓存隔离、脚本独立安装及来源选择、退出不影响其他用户、切换取消和持久化失败、设置多行与图标、添加后返回已有用户。回滚时停用 Profiles 入口，新用户目录保留但旧版本只识别原 default 数据；不得把新 Profile 库合并回旧根目录。索引与隔离实现不等于人工签收。

2026-11-01 验证：合成账户的旧库迁移/重启、同校不同用户凭据和缓存、独立脚本安装、退出隔离、索引写失败/损坏、切换中的晚到输入，以及实际应用添加/切换/设置多行交互均通过；已有手动登录与取消回归随 Profile 详情入口调整。自动回归不构成人工凭据安全签收。
