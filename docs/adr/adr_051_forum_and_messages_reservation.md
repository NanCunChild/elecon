# ADR-051 论坛、消息入口与独立服务账号规划

- **Decision**：入口预留 Accepted（2026-11-01，所有者要求规划与预留）；服务选择、账号实现、领域契约、写操作及推送为 Proposed。
- **Landing**：本轮仅增加论坛/消息原生占位页与导航，以及实施计划；无论坛数据、账号存储、登录接口或后台服务。
- **安全签收**：本轮不新增认证/网络实现；后续核心、凭据与网络实现仍须人工实质审阅。
- **范围**：承接 ADR-041/042/044/047。论坛不是 notice，服务账号不是本地 Profile，也不自动等同学校身份。

## 决策与本轮范围

主壳预留“首页 / 论坛 / 消息 / 设置”四个原生入口，Material 与 Apple 玻璃底栏使用同一份 tab 定义。占位页明确显示筹备状态，论坛说明主题与回复的方向，消息说明回复、提及与站内消息的方向；提示未来可能需要额外服务账号。不显示虚构帖子、已登录状态、零未读或可点击的假登录按钮。

占位页只展示本地 zh/en 文案，不读取学校凭据、不触发脚本、登录、轮询、推送或网络访问。保留首页卡片布局与现有学校登录操作。后续分别替换两页内容即可接入业务，无需再把论坛塞进首页卡片。

数据来自学校已有论坛还是 elecon 自有社区，本轮尚未决定；不假设任何学校开放论坛接口，不新建可安装的伪能力声明。选型与下一步设计见[实施计划](../planning/forum_and_messages.md)。

## 后续账号边界（Proposed）

本地 Profile 是存储和会话边界。服务账号在其下记录明确的 service/provider、远端稳定 account ID 与展示名；同一服务的论坛与站内信只有在服务确认相同主体后才共用会话。学校账号、论坛账号和消息来源可分别过期、退出与重新登录。不能根据学号、昵称或学校已登录状态静默绑定账号。

当前 SDK 2 namespace 不是权限隔离，同校受信脚本能显式共享凭据。后续若使用脚本接入独立论坛账号，安装授权必须解释其实际信任范围；若需要学校脚本无法读取的账号库，须另立宿主认证/存储 ADR，不能只增加 namespace 就声称隔离。当前不实现任一新凭据存储方式。

服务凭据与私密消息由客户端直连目标服务，不能经过静态公网分发服务或公共中继。若选择自建社区，私密消息服务及数据处理将改变现有服务职责，必须先有独立后端/隐私/授权决策；现有 `server/src/public` 不承担该功能。

## 验证与回滚

自动回归覆盖四入口导航、深浅主题、窄屏大字号与中英文筹备文案，并验证进入占位页不会请求业务能力。既有应用启动与 Profile 设置回归继续适用。自动测试不代表服务可用、学校授权、真实账号或真机验收。

回滚只移除两个导航项与占位页；本轮没有账号、缓存或契约迁移。未来服务实现应按独立切片回滚，不回收远端实体 ID 或把私密消息改成通知缓存。
