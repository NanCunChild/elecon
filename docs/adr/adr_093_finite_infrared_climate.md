# ADR-093 · 有限红外方案、原生发射与无回读空调状态

- 日期：2026-11-05
- 状态：**Proposed**。本文为可审阅的契约与实施提案，未接受、未实现；不分配已可用 SDK 版本，不向当前 manifest 加权限。
- 承接：ADR-045、046、080、092；证据入口为[校园体验研究](../research/campus_experience_android_2026_11_05.md)。

## 问题与选择

网络空调状态来自远端回读；手机红外只发送波形，无法证明空调收到或采用指令。不能复用 `climate.command@1.0` 的 `applied`，也不能用最后一次发射把 `climate.status.power` 填成真或假。纯红外页面不应以拥有互联网绑定或 `climate.status` 为前提。

提议采用独立红外能力及宿主端口，保留 ADR-092 的网络路径。学校包提供有限型号方案、协议编码、目标值约束和说明，核心负责原生选择/按钮、包授权、硬件与波形预算。核心不内置学校/品牌协议，不开放原生插件、FFI、任意文件或从其他遥控应用提取码库的能力。

**目前没有经确认的学校空调型号、获授权的有限红外码表或对应编码实现来源，也没有真实发射/接收验收。** 有红外硬件的系统声明仅证明有候选平台能力。实施前需取得至少一个具体型号、可再分发的方案来源/许可证、独立编写或可兼容引入的编码器及实际接收证据；不能先放虚构方案让用户试射。现有网络页可独立交付。

## 候选契约

以下名字和版本均为提议，接受后同步 registry、schema、SDK、准入与作者手册：

| 能力 | 提议含义与约束 |
|---|---|
| `climate.ir.schemes@1.0` | 只读有限目录，最多 64 项；每项含稳定 `schemeId`、独立 `schemeVersion`、名称、型号说明、支持的命令和目标值约束。方案编号仅为 UI 序号。返回 `frameMode: discrete/fullState`，后者显式给出必须提交的目标字段。目录读取和选中都不发射。 |
| `climate.ir.binding@1.0` | 返回当前身份下的 `unconfigured/configured` 及稳定方案引用、设备显示名、可选本地目标值；引用含包 ID/digest 和方案版本。没有 observed power、室温或“在线”字段。 |
| `climate.ir.configure@1.0` | 前台普通请求，参数是目录中一个方案引用及用户填写的配置。保存本地绑定，不发射。解除绑定同样只改本地配置。脚本不得把配置入口当作隐式测试按钮。 |
| `climate.ir.command@1.0` | 前台明确的测试/控制按钮发起，参数含当前绑定引用（测试时为用户选中的候选方案）、`purpose: test/control`、命令及完整所需目标值。测试候选使用宿主短期选择租约，不因未保存而扩大范围。一次请求至多一次原生发射；完整状态协议缺任一必要字段时拒绝，不能猜测网络设备的缺失状态。 |

命令结果区分 `transmitted`（原生调用正常返回）、`notTransmitted`（已确定未发射）和 `unknown`（已进入原生调用但结果未确认）。结果可包含宿主生成的调用 ID、发送时刻、标准原因码及所发送的目标值；没有 `applied`，不能由业务脚本输出一段文字冒充宿主发射回执。时间来自该次原生执行，不以缓存恢复时刻重写。

本地目标值属于“拟发送/上次发送的设定”，与远端观测分别显示。更改温度选择器不自动发射；用户点发送时重新验证方案、范围及完整帧。首片显式“开”“关”按钮，协议仅有 toggle 时标为“切换”并说明实际状态未知，不能把 toggle 命名成幂等开/关。室温始终缺失，除非另有明确独立观测来源；不能把设定温度显示为室温。

## 宿主端口与发射预算

候选端口为 `elecon.infrared.hardware()` 与 `elecon.infrared.transmit(...)`，只对新 SDK 明确声明红外能力的批准包开放。安装审查展示可发射红外及其有限方案；Android 系统权限不替代这一步。namespace 仍不是同校包之间的最小权限沙箱。

`hardware()` 不发射，返回 `available/unsupported/unavailable` 及硬件报告的载波范围。`transmit` 接收当前批准方案引用、`carrierHz` 和交替开/关的 `patternMicros` 正整数数组。编码在受信脚本中，原生层只接受数据，不加载作者原生模块。宿主核验方案属于本次批准包和用户当前选择；这不证明波形确实适用于声明型号，编码/型号一致性仍需协议测试和人工审阅。

建议首片使用可配置但有上限的预算：

- 单波形最多 4096 个正整数脉冲，使用宽整数累计，包含重复帧/间隙的总时长严格小于 2,000,000 µs；单项不能溢出平台整数。拒绝零、负数、非整数、NaN 和超界数组。
- 频率须在 10,000–1,000,000 Hz 的宿主上限及设备报告范围的交集中。设备范围读取失败时返回不可用，不把缺失范围解释成支持任意频率。
- 全设备单通道串行；每个按钮请求只允许一条波形，协议必需的重复帧由编码器包含在该波形内并计总预算。首片不提供连发/学习模式，不因超时或未知结果自动重复。
- 排队前及开始发射前核验前台执行租约、Profile、学校、批准 digest、选中方案、取消和单次消费标记；包内其他能力不能凭持有引用借用测试/控制租约。
- 取消阻止尚未开始的发射；开始后只能标记界面/调用失效，不能声称物理信号已撤回。进程在原生调用中退出时保留未知状态，不在重启后补发。

预算数字是首片设计限制，不是兼容型号或硬件性能的实验结论；若实际授权方案需要扩大，须以协议和资源测量调整版本，不能绕过限额。

Android 首片可直接使用 Kotlin 桥接 `ConsumerIrManager`，在工作线程执行同步 `transmit`；官方 API 使用 Hz 与 µs，且只接受短于两秒的模式。[Android ConsumerIrManager](https://developer.android.com/reference/android/hardware/ConsumerIrManager)

实施时增加 `TRANSMIT_IR` 声明并将 `android.hardware.consumerir` 标为可选；无硬件设备仍可安装和使用网络空调。该系统权限为 normal，业务授权和前台按钮边界仍由宿主落实。[Android 权限定义](https://developer.android.com/reference/android/Manifest.permission#TRANSMIT_IR)

## 页面、迁移与许可

新 SDK 的原生 climate 页面允许网络能力、红外能力或二者同时存在。没有绑定时提供实际声明的配置入口；纯红外来源无需伪造 `climate.devices/status`。有/无硬件分别显示方案选择或“不支持红外”，不自动切换模式。用户主动选择方案后可独立点“测试开/关”，观察设备反应，再保存方案。按稳定引用保存，不依赖目录排序。

网络请求失败或结果未知时保留其结果；绝不自动发射红外补偿。用户后续主动点红外按钮是另一独立请求，界面仍显示原网络操作的未知状态。前台结果未知也不因重新打开页面、刷新或缓存恢复而重放。

接受并实施时递增 SDK 并明确红外权限、目录和页面准入版本。旧包没有新端口；旧宿主拒绝新 SDK/未知能力，`climate.devices@1.0/1.1`、`climate.status@1.0`、`climate.command@1.0` 的含义不变。包更新使旧方案绑定待重新选择/确认，不能把同 ID 的新波形沿用旧批准 digest 执行。回滚禁用新红外入口并保留可清理的本地配置，任何新/旧包重新安装仍批准精确 digest。

首片无需第三方 Android 红外库。每套码表、型号资料、编码器及生成数据分别登记来源、版本和许可证；不能从闭源遥控器应用提取未授权资源。GPL 系编码实现或码库如拟引入，先确定模块/进程及分发边界，不能以改写或“只复制数据”跳过许可审阅。提案阶段未引入依赖、权限或码表。

## 接受后的验证与关闭条件

合成测试覆盖目录/方案引用、未知版本、完整目标字段、波形整数/频率/总时长/并发预算、未批准/错误学校、取消排队及开始后未知、去重、后台/预加载/缓存恢复不发射、网络未知不转红外。原生桥 mock 验证一次调用和回执分类；UI 验证无硬件、纯红外、未知状态、来源变更、窄屏/大字号及读屏。

平台验收需同时覆盖有/无红外设备、授权方案对应真实空调、载波/波形及设备动作、运行中离页/锁屏/进程退出。设备安装及 UI 检查不等于发射成功，发射成功不等于空调采用目标值。所需型号/合法码表/真实硬件证据和核心控制人工审阅到位后再接受实施；本 ADR 不提供验收或发布结论。
