# ADR-042 能力提供者、独立页面与增强包

- **Decision**：Proposed（2026-10-31）。本轮授权是研究与文档规划；以下新的 SDK、权限和接口不是已接受或已实现的产品能力。
- **Landing**：未实现；代码观察见[接口审计](../reference/interface_evolution.md)，分期见[计划](../planning/platform_evolution.md)。
- **依赖**：[ADR-041](adr_041_current_architecture.md)当前基线、ADR-034/035/038/040。
- **不修改**：现有 SDK 1–5 语义、manifest、schema、控制门和 V1 入口。本 ADR 内类型和字段均是设计记法，不能直接放入现有包。

## 1. 问题与目标

当前注册表按安装顺序隐式选择 provider，更新包也可能改变默认来源；首页手写各能力分支，查询状态和 Widget 混在一起。列表详情会重新解析 provider，分页 decoder 丢失元信息。这些现状会妨碍主包与增强包共存，也使论坛、独立课表和图书检索不断向首页增加条件。

兼容性的目标是让新学校只适配数据、新页面复用能力、新来源显式接入，且每层含义可验证；不是让任意 JSON、任意脚本依赖或未知版本都被接受。第一版只支持增强包补充能力或替换只读 provider，不建立通用脚本调用图。

## 2. 六种对象分别定义

| 对象 | 负责 | 不负责 |
|---|---|---|
| CapabilityDefinition | 业务操作 ID、query/command 分类、参数及结果版本、分页/缓存/副作用语义 | 指定学校、包或 Widget |
| Schema | 具有明确单位、缺失值和版本的数据结构 | 决定数据来源或权限 |
| Provider | 某安装包对特定能力和版本的实现，受其授权及可用条件限制 | 静默覆盖其他 provider |
| MainPackageBinding | 用户选择的学校基础包及其能力默认集合 | 将安装顺序解释成主包角色 |
| EnhancementBinding | 增强包对目标主包/能力的显式补充或替代关系 | 默认继承主包凭据、网络或浏览器权限 |
| FeatureDefinition / PageDefinition | 客户端内建业务组合、必需/可选能力、路由参数、模板和交互 | 接受脚本下发任意 Widget tree |

当前 manifest 仍要求 `schema == elecon.<capability id>`，第一阶段保持此映射并从 registry 生成输入输出绑定；只有确有多能力复用同一结果模型时另作兼容增量。不要为了抽象漂亮先改完所有已有 schema。

## 3. 主包与增强包组合

### 3.1 描述与兼容检查

增强描述至少说明稳定包 ID、目标学校、目标主包 ID（可选严格绑定）、支持的主包版本集合/范围、最低宿主 SDK、提供的能力及输入/输出版本、补充或替代模式、权限 profile、网络范围。以能力语义兼容为主，只有依赖主包实现细节时才约束具体主包版本。

安装时验证声明和宿主支持集合，生成可审阅的候选关系；用户显式启用指定能力。一个学校可装多个增强包，但同一 query 默认绑定一个 provider。仅安装和更新不能抢占绑定。原有安装迁移逐能力保存当时实际选中的 provider pin，不假定全部能力属于单一主包；用户可再显式选定主包。既有 list/detail 如已异源则标记待选择或不可用，不自动拼成绑定组。不把旧包自动提升为拥有新权限的增强包。

首版保持单校单活动账户，预留独立 IdentityId，不能将 schoolId 当作账户标识。切换账户须使旧请求上下文与私密缓存全部失效；正式同校多账户模型在私密增强前完成。

一次请求解析后固定 `(identity, capability, inputVersion, outputVersion, packageId, digest, bindingRevision, sessionGeneration)`。列表、详情、分页、缓存和取消都携带这一上下文。更新/卸载/切身份使旧上下文失效；新包继续该绑定前须验证兼容和重新授权，不以 digest 改变偷偷换来源。

### 3.2 解析顺序和失败

1. 校验当前身份、能力参数和明确的绑定；排除禁用、版本不支持、未授权的候选。
2. 若有显式增强绑定，执行其 provider；否则执行主包默认 provider。
3. query 仅在用户选择的降级策略内回退一次主来源。只允许网络/暂时不可用等预定错误；解析错误、权限拒绝、版本不兼容不以自动重登录或跨权限查询掩盖。
4. 回退必须有同版本语义或显式转换器，标明来源；详情/游标不能直接带入另一 provider，须回到列表重新查询或使用已验证实体映射。
5. 首版不把多个 provider 的数组直接拼接。不支持任何 command 跨 provider 自动回退。

未选择的增强包不参与 preload；能力可用性根据实际绑定计算，不对所有安装包取并集。禁用增强包恢复先前仍兼容的主绑定；主包缺失或不兼容则显示不可用，不能选择另一个任意包补位。

### 3.3 权限不是 namespace

SDK 1–5 学校脚本按 ADR-035 可访问本校各 namespace。**不能把这种包换个名称就当成低权限增强包。** 首个匿名增强试点要求新增、明确版本化的宿主 profile：无 credentials API、无浏览器、无凭据型输入表单，只有声明的公开网络和只读能力；宿主不向其提供私密参数/缓存，也不复用学校浏览器会话或认证 Cookie。拒绝未知 profile，安装 UI 展示权限差异。

query 是业务契约，不是对任意 JS 的只读沙箱证明；origin 白名单也不能阻止同站写请求，GET 仍可能有副作用。匿名首版只允许经过审计的静态公开快照端点与方法，在宿主覆盖模块初始化和 handler 的全部出网、重定向及参数通道，拒绝未声明路径/方法和写入口；源站操作语义仍需审计，不能仅靠 HTTP 方法声称安全。

旧脚本保留原有高信任语义并明确展示。包若从匿名 profile 升级到身份能力，必须升包/SDK 版本并重新授权；不能依赖 namespace 或主包依赖关系自动获得访问权。

需要私密数据的增强包作为后续独立设计：用户明确授权给谁、哪一身份、哪些能力/数据、期限和撤销方式；优先由宿主执行主包标准 query，交付有类型最小结果，不直接共享整个凭据库。SDK 2 的同校存储并不证明同校多账户隔离已实现，该设计前先补账户身份模型与测试。

## 4. 输入、输出与错误的确定语义

以下类型是目标概念，不是现行 wire schema：

```text
QueryRequest = binding + capability + inputVersion + normalizedParams
QueryResult<T> = data:T + schemaVersion + providerContext
               + freshness + completeness + pagination?
EntityRef = identityScope + datasetId + providerContext + entityType + localId
```

元信息由宿主装配可验证的部分，不能只信任脚本自报。“来自公共缓存”是传输来源，不代表数据真伪或官方背书。新 query 结果与现有数据信封统一或转换前须定义单一版本映射，避免出现两个含义不同的 freshness。

| 面向 | 约定 |
|---|---|
| 参数 | registry 为每能力显式绑定参数 schema；先验证再执行。默认值归一后用于缓存键，拒绝未知 command 字段和无效组合；旧开放 query 参数通过版本迁移处理 |
| 版本 | 包三段版本、SDK 整数、schema major.minor 各自独立；只接受宿主支持的精确版本/已验证转换，不按“同 major”盲收 |
| 缺失 | absent 表示来源未提供；null 仅在 schema 声明时有其特定含义；空数组表示完整查询零条；失败、部分结果不得伪装成功空集合 |
| 分页 | offset/page 或 opaque cursor 明确区分；cursor 绑定来源、身份、过滤、排序；total 可未知；partial/hasNext 明示，禁止 decoder 丢弃分页元信息 |
| 时间 | `*At` 为时刻，`*Date` 为日历日；学校时区、教学周、节次和墙钟分别建模。旧日期转确定时刻约定保留旧版，不在新版凭空制造精度 |
| 数值 | 金额用最小单位和币种；用量与累计读数分别表示并带单位；未知不填 0，复本可借状态不推导全馆库存 |
| 错误 | 稳定类别区分取消、未认证、拒绝授权、网络、限流、源站、解析、版本和不支持；安全文案及可选 retryAfter，不直接显示原始响应/秘密 |
| 命令 | 续借、预约、发帖、回复、举报、空调控制均属副作用操作；不因 HTTP GET 或输出形似列表而归 query |

已有 `CapabilityRun`、错误类型和数据信封不足以证明这些字段已全部接入。先在宿主内部建立兼容 facade，旧脚本返回值由适配器补足已知信息；未知保持未知，不能伪造源站观测时间。

## 5. 数据源与缓存

本地私密缓存键至少包含身份、绑定、provider/digest、能力/数据版本及规范化参数。公共快照只处理公开查询，用数据集/解析版本、能力版本与公开参数分区；不得把学生标识或凭据送到公共键空间。

`observedAt`（源事实时刻，可能缺失）、`fetchedAt`（采集成功时刻）、`servedAt`（本次送达）分别记录；读缓存不能刷新采集时间。页面显示实际来源、新鲜/过期、部分与失败状态。TTL、硬过期、后台刷新和离线保留按能力策略决定，从 `manifest.home` 的首页专用设置逐步提取；旧缓存仅在兼容适配层保持行为。

通知列表/正文固定相同 dataset 和来源；教室楼栋/空闲结果共享实体命名空间；馆藏书目/复本/借阅记录互不混淆。跨源合并将来必须有版本化 recipe，定义实体映射、去重、排序、冲突和部分失败；限制依赖深度、预算和循环，第一版不实现脚本互调。

## 6. 独立页面和模板

| 页面 | 已有基础 | 需要的明确增量 |
|---|---|---|
| 独立课表 | `schedule.week`、`term.list`、`calendar.academic` | 提取共享 QueryController、周/学期切换和路由；教学周与真实日期不能由页面猜测 |
| 课程标准/大纲 | `course.catalog` 仅目录 | “课标”按不同于课表的业务预留 `course.syllabus`/详情语义，需独立领域 ADR；不得塞进 `schedule.week` |
| 图书查阅 | `library.loans` 是个人借阅 | 新增书目 search/detail、馆藏复本；书目 ID/ISBN/复本条码/借阅 ID 分开；公开检索与私密借阅分开授权 |
| 论坛 | 可复用列表/详情/分页/有界正文组件 | board/thread/reply 的领域模型及作者、楼层、删除/审核状态；首版只读；不能复用 notice 字段改义 |
| 通知增强 | `notice.list`/`notice.detail` | 补标准详情入参、完整分页、稳定实体引用、撤回/过期与来源展示 |
| 空教室/水电 | 已有教室与水电 schema | 参数、时间范围、结果完整性和授权分区；查询页不因中继存在变成公共数据 |

`PageDefinition` 在客户端注册稳定路由、类型化 route params、required/optional capabilities、可用条件与页面工厂。缺必需能力显示明确不可用；缺可选能力局部降级。`FeatureDefinition` 组合 repository/controller 与摘要/完整页面，使认证、刷新、分页和取消不依赖首页 Widget 生命周期。

只提取已经重复的组件；不引入新的 UI DSL，不提前抽象所有未来论坛写操作。富正文由宿主限界渲染并检查外链，不执行文章脚本。

## 7. 中继增强的首个垂直切片

匿名公开通知：独立公开数据采集服务 → 版本化快照/ETag → 无凭据增强 provider → 显式列表/详情绑定 → 页面展示来源/采集时间 → 禁用恢复主包。不复用 `server/src/public` 静态发布职责，不上传学生 Cookie，不宣称 Node 已能执行新学校包。

共享采集可以复用经拆分的纯解析模块，但服务端 runner 是单独可信部署组件，来源白名单、重定向检查、大小/超时/请求预算独立实现。空教室需学校授权后试点；水电优先客户端身份缓存，不做全校缓存。详细证据、限制与验收见[研究](../research/relay_enhancement_feasibility.md)。

## 8. 验证与待决问题

实施必须覆盖：安装/更新不抢绑定、禁用恢复、版本不匹配、两个 provider 的同名不同 ID、详情与 cursor 固定来源、迟到结果被代际拒绝、匿名包不可读凭据/浏览器/私密输入、跨身份缓存隔离、命令不走预加载或自动回退。

接受前明确：新增 SDK/profile 编号与声明格式、同校账户身份迁移、学校共享发布授权、source/freshness 与现有 envelope 的唯一映射、首批支持的精确版本。用户的“课标”含义未明确前分别保留两个概念，不为其中一个作实现承诺。技术规划可以继续细化，生产部署、权限实施和人工签收按各切片事实记录。

## 9. 未采用

不使用安装顺序或通用优先级数字决定提供者；不允许增强包自动继承凭据；不将所有页面塞入 generic.section；不把论坛映射为通知；不把 schema 增加等同于页面已可用；不以给每个层加任意 Map/插件接口来声称兼容。
