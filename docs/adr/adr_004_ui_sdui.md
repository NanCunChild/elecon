# ADR-004：UI 层——数据驱动 / SDUI 的具体形态

- **状态**：占位（Placeholder） 核心取向已确定，具体 schema / 渲染协议待展开。
- **日期**：2026-06-14（占位），待正式展开
- **依赖**：[`adr_000_abstract.md`](./adr_000_abstract.md)（§2.2 分层、§4 "数据驱动 / SDUI"）、[`adr_001_contract.md`](./adr_001_contract.md)（标准 schema / generic 域）
- **适用范围**：UI 层如何消费标准 schema 渲染卡片；typed 域 vs generic 域的渲染策略；adapter 与 UI 的职责边界。

---

## 1. 核心取向（已确定，待正式 ADR 展开）

以下决策在架构讨论中确立，记录于此以防误走歧路：

### 1.1 保留 typed 模型——本体"认识"数据

UI 层理解数据语义（成绩、课表、通知等），**不退化为纯渲染引擎**。理由：

- 本体需要**计算**（GPA、排序、语义搜索、跨校聚合）。
- 本体需要**行为**（课前提醒、截止日期提示）。
- 一致性：20 个学校走同一套视觉语言，不靠 adapter 各自定义。

### 1.2 adapter 提供语义角色提示，绝不提供样式

- **adapter 可以给的**：标注字段的语义角色（状态 / 截止时间 / 金额 / 主标识 / 链接）。
- **adapter 绝不能给的**：颜色、控件选择、布局代码、CSS 类名。

adapter 说"这是个 deadline"，**本体的主题**决定 deadline 长什么样。

### 1.3 generic 域兜底长尾数据

`elecon.generic.section`（ADR-001 已预留）：受约束的"带标签字段 / 键值组 / 简单表格"，配合角色枚举，覆盖不值得单独立 typed schema 的校园特有数据（宿舍水电、实验室预约等）。**本体仍拥有渲染权和样式**，generic 域不等于 adapter 自由布局。

## 3. 被拒绝的方向（已否决）

| 方向 | 否决理由 |
|---|---|
| adapter 提供样式/控件/布局 | 拆一致性、放大 adapter 攻击面（可伪造误导 UI）、blast radius 不可控 |
| 全部抽象为"样式命名 + 变量由 adapter 提供" | 本体退化为浏览器，失去计算/提醒/聚合能力——产品价值归零 |
| 完全放弃 generic 域、一切走 ADR 慢车道 | 摩擦过高，冷门数据无法快速上线 |
