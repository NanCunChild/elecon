# ADR-092 · 本地空调绑定、扫码与独立状态

- **Decision**：Accepted（2026-11-05，所有者授权按校园体验研究实施）。
- **承接**：ADR-040 的领域模型、ADR-045 的扫码权限、ADR-046 的普通请求与未知结果语义。

## 决定

`climate.devices` 输出升为 **1.1**：设备列表表示当前学校身份保存的用户绑定及有限控制能力，允许离线读取，不再要求每次列出绑定都先访问远端。本地绑定不证明当前在线、授权仍有效或命令可达；当前读数仍只由独立 `climate.status@1.0` 提供，状态失败保留绑定卡并显示未知，禁止乐观状态及自动重发。

设备必填 `deviceId`、`label`、`commands`；温度范围、模式/风速及联动配置只在支持相应操作时提供。宿主逐操作检查元数据和所需当前状态：开关只需已知 power，温度加减需已知设定温度和范围，其他操作不因无关字段缺失而被一并阻塞。状态在线标记为 false、有设备错误、正在请求或未回读时仍不能操作。模式联动继续使用完整 `modeDefaults`，不猜测缺失的设置。

可选 `bindingVerifiedAt` 表示脚本最后成功通过只读状态核验该绑定的时刻，RFC3339；不是当前状态观测时间。旧本地绑定缺该值时省略，不能用当前时间补造。`climate.status` 和 `climate.command` 版本及单次控制后一次查询语义不变。

西电在 `configure:true` 的显式用户操作中选择扫码或手输。扫码复用已有 SDK8 `scanner` 权限，不新增相机依赖；脚本只解析 15 位 IMEI 文本，或固定 `https://gxkt.juhaolian.cn` 来源中唯一的 `imei` 查询参数，其他格式明确拒绝。提取后在原生输入页显示待绑定标识供用户核对，再使用固定状态端点核验；扫描 URL 从不作为请求地址。取消、拒绝权限、非法内容或核验失败都保留旧绑定。只有成功核验后才替换受保护的同校记录；未绑定时仅显示入口，不自动扫码或控制。

原生页面顶部展示绑定设备与改绑入口，设定温度和室温分开显示，缺失用未知占位；其余控件按设备支持项呈现。主面板只承担网络控制，本片没有红外回退、无回读状态或纯红外入口。

## 兼容与验证

保留 `climate.devices@1.0` 精确 schema；新脚本升包版本、声明 1.1 和 scanner 并重新批准 digest，旧宿主拒绝未知版本。旧包继续原实现，不能通过客户端缓存悄悄替它改义。回滚恢复声明 1.0 的旧包并按正常流程重新批准；不修改已授权字节。无新增依赖、网络来源或公网中继。

合成测试覆盖离线列绑定零网络、扫描格式/取消/拒权、旧记录保留、核验后保存、仅开关设备、设定/室温未知、窄屏/大字号、单次发送/未知不重发及页面/身份失效。学校源码需 Node 与真实编译包 QuickJS 分别验证。没有真实扫码标签、学校设备控制或硬件发射验收；核心控制实现须人工实质审阅后合并。
