# ADR-066 · 功能来源、账号状态与脚本声明的 APPTunnel

- 日期：2026-11-02
- 状态：Accepted（所有者授权抽象解耦、多同型卡片、学习通知、账号状态、APPTunnel 与消息语义）
- 承接：ADR-034、043、044、052、058、061、062、064、065。

## 功能与来源

将 `capability_sections.dart` 拆为领域组件与共享查询状态，将 `schema_decode.dart` 拆为独立领域解码器；保留导出入口。共享查询抽象承担调用、来源绑定、缓存时效、缺配/认证/失败状态和代际失效，领域组件负责标准数据与交互。解码保留列表分页元信息，不把失败当成空集合。

SDK 12 为有限 `cards` 增加可选包内稳定 `id` 与纯文本 `title`。未给 id 时使用 type；同包 id 唯一，同 type 可有多个 id。实例由声明包、卡片 id 与模板类型确定；批准 digest 决定其当前执行字节。原生布局分别保存各实例顺序、尺寸、显隐；新增实例不抢占其他来源。已有无 id 卡片沿用默认来源展示，新显式实例固定同包执行，不改变全局 capability override。详情、重试、登录、缓存均保留实例来源；撤销、禁用、更新或切身份使旧结果失效。

仅已有原生模板可实例化，所需能力必须同包具备；不接受 Widget tree。显式实例所声明的只读 home 查询可独立预加载，缓存按学校/Profile/来源 digest/能力/参数隔离。账号、控制和发送不预加载，多个实例不能触发命令自动重发。

## HTTP 学习通知

超星增强包新增 `notice.list` 与名为“学习通知”的独立 notice 实例，学校通知继续存在。本地 Quasar-core 用于确认独立 HTTP 通知模块及字段事实。真机确认其 `myNotices_v2` 接口拒绝当前来源 IP，因此实际使用官方 PC 前端的 `POST https://notice.chaoxing.com/pc/notice/getNoticeList`，携带当前账号 Cookie，使用与官方页面默认一致的当前上海年份收件筛选。`idCode/sendTag` 组合是该入口的稳定实体标识；合并置顶/普通通知并去重，列表正文供本地详情。源站 `lastGetId/lastPage` 在脚本内转换为有界页码请求和分页元信息，不新增未声明的 cursor 入参。不冒用环信消息，不调用标记已读、回复或通知发送；访问拒绝不解释为认证失效或空列表。

Quasar-core 为 GPLv3，仅研究协议事实，不复制其实现；本仓新增 JS 与合成测试独立编写，记录来源及许可边界。不提交真实通知、身份或凭据。

## 账号状态与凭据有效性

SDK 12 账号声明可绑定同包 `status` 只读调用；标准 `account.session` 1.0 返回 authenticated/signedOut/expired/unknown、可选账号标识/显示名及检查时间。没有凭据且无已确认失效记录为未登录；只有脚本或内置服务确认失效才是 expired；超时、网络故障和无法确认必须保留 unknown。凭据条数、一次能力成功、页面返回不等于已登录。

账号页面查询脚本状态，已登录展示账号信息与重新登录，未登录/失效提供登录入口，失效给出明确提示；未知状态允许手动检查/登录。账号页前台无交互检查不得弹浏览器/表单或发登录密码，后台账号执行拒绝；普通账号 login 必须返回脚本已核验的 authenticated，返回账号页后重新检查 status，并沿现有受保护持久化与代际门更新凭据。失败/取消不假报成功，不用晚到结果覆盖新身份；学校服务与社区账号分别判定。

## APPTunnel

界面统一称 APPTunnel。Hermes/aTrust 是宿主固定内置传输实现，SDK 12 包显式声明 `appTunnels: ['hermes-atrust']` 后才可调用受限 `ctx.appTunnel.status/login`。脚本把该服务作为账号声明与编排，宿主继续管理输入、密钥、TLS 与受保护会话；不返回密码、Cookie、原生句柄，不允许动态加载隧道实现。

登录是前台显式调用，经宿主固定入口完成；检查只返回标准账号状态。管理调用不得因尚未建立隧道而不可执行，但该例外只提供宿主管理端口，不授权学校 HTTP 绕过路由。登录不隐式选择路由，失败不直连回退，切换不自动重发业务请求。Hermes 认证发布撤销旧脚本执行，登录页待管理页返回后用新代际重新查询同包状态再判定成功；仅打开管理页后返回视为取消，不把旧会话当成本次新登录。Profile/学校/来源授权、取消、网络预算继续执行。旧 SDK 不得使用新声明/API。

## 消息与发送权限

消息契约新版本区分 text、activity、command 等已知类型；活动与指令仅作标识/摘要，不执行指令、不自动打开或提交活动。会话/历史返回当前账号的 sendPermission：allowed、muted、unknown。脚本根据源站群级、成员级禁言及豁免信息归一；缺少证据不推断可发言。核心据当前会话状态禁用已禁言/未知发送并显示原因；脚本发送前继续验证权限。旧版本按原 schema 读取，不静默增加允许发送的默认值。

## 验证与交付

同型双卡片覆盖不同来源的列表、缓存、详情、刷新和撤销；账号验证状态矩阵、失效与重登、取消和持久化失败；APPTunnel 验证未声明/后台拒绝、身份失效、无秘密返回与无直连回退；通知与消息采用合成协议回归。设置与布局在窄屏、深浅色、语言和文字缩放下验证，授权有线设备安装与点击检查。

开发阶段允许不迁移旧卡片布局/旧脚本，但声明、SDK 与消息 schema 明确升版；包需重新批准。核心、凭据、网络与传输变更仍待人工实质审阅后合并。自动检查、真实学校业务、真机导航与人工签收分别记录。分步不签名提交，保留此前未提交工作的归属。

## 实施补充

完整展开卡片保留持久化整数逻辑格，按实测内容高度压缩全宽物理行；后续各列统一移动，拖拽与渲染共用可逆映射。半宽/小卡片的既定尺寸不变。拿起尚无持久化坐标的卡片前先固定当前排布，避免拖动时跳到第一行。
