# ADR-060 · 本地缓存优先启动

- 日期：2026-11-02
- 状态：Accepted（用户授权实施；核心实现仍需人工实质审阅后合并）
- 承接：ADR-034、ADR-038、ADR-043、ADR-044

## 问题与决定

启动当前先加载所有 Profile、访问 V1 分发目录，再恢复已授权学校脚本，主页读取也可能启动查询。这把与缓存阅读无关的网络和脚本等待放进全屏启动门。

启动只先恢复当前 Profile；其它 Profile 在选择时初始化。会话先恢复本地已授权脚本及选校，对已有脚本学校不等待 V1 远端目录；V1 学校保留原有验签、吊销及执行门，不将展示缓存当执行授权。bootstrap 的并发调用共享同一 Future，失败不能被当作完成。

主页的 cache-only 装配严格只读本地数据及已批准来源信息，不运行 JS。学校卡片布局继续使用 ADR-043 的非密学校范围文件，增加进程缓存并在首张桌面显示前恢复，切校不串用布局。首个已恢复桌面帧之后再调度后台刷新；缓存阅读及页面交互不等待引擎，后台成功只更新相关缓存，失败保留原数据与时效。短暂本地存储恢复期间使用稳定的非阻塞占位，不使用全屏强制旋转动画；DEV 侧载水印例外仍按 ADR-024。

不把个人课表、余额或凭据复制进明文桌面缓存；它们仍需经当前身份的 H/S/M 解锁、当前来源和 schema 校验。硬件解锁失败的旧清除策略由 [ADR-095](adr_095_protected_store_recovery.md) 替代：保留密文、阻断使用并允许显式重试，不以缓存绕过。

## 验证与回滚

测试阻塞的远端目录不影响已安装脚本学校恢复、非活动 Profile 延迟初始化、并发 bootstrap、cache-only 零执行、布局持久恢复与切校隔离。真机观察单独记录，不将测试时长写为性能收益。回滚可恢复原启动顺序，不迁移业务数据和安装授权。
