# ADR-055 签到地点矩阵与明确失败原因

- **Decision**：Accepted（2026-11-02，所有者要求排查学习通签到并在页面指定位置）。
- **Landing**：契约、原生矩阵、独立地点存储及社区包 0.2.0 已实现，合成协议/真实 QuickJS/存储/页面回归通过；设备与真实活动验收另记。承接 ADR-044/045/046/052/053；第三方包继续手动导入。

## 契约与交互

`attendance.checkin` 1.1 的参数新增可选 `location`，包含有限范围的 latitude/longitude（十进制度）、address（1–200 字）及 `coordinateSystem=service`。这里明确表示该服务所要求的原生坐标，须从同一服务的地点数据取得；不猜测地图供应商、不转换坐标、不声称手机实测 GPS。位置缺省时不提交自造坐标。保留 1.0 空参数及原输出校验快照；只有声明 1.1 的来源显示地点矩阵和接收新参数。SDK 权限不增加。

原生页面提供最多 16 个可添加、修改、删除的地点按钮，显示名称与坐标，用户选择后才在下一次主动扫码提交中传入。每次进入页面默认不选择地点，不自动沿用上次提交位置。地点按本地 Profile、学校和 provider ID 保存于已有 H/S/M 后端的保留地址，更新同一包可继续使用；切来源/学校/Profile 不混用。UI 通过仅暴露地点的窄接口读取和保存，不获得凭据库。地点不计为登录凭据，不可通过 ScriptCredentials 枚举或寻址；仅本次选定位置进入脚本参数。退出学校沿既有清除规则删除，服务账号退出不删除用户地点。

结果增加可选固定 `reason` 枚举：location_required、location_rejected、face_required、photo_required、verification_required、activity_unsupported、requirements_unknown、qr_expired、request_failed、submission_rejected。UI 显示本地化原因，不回显源站正文、Cookie、QR 或设备字段。未观察到具体原因时不编造；unknown 继续表示提交可能发生，禁止自动重发。

## 学习通适配

脚本两次检查活动要求：只在类型明确为 QR 且人脸/验证码要求显式关闭时进入提交；定位要求开启则必须有本次所选地点。未知/缺失必要标志继续拒绝，不将未知改为无挑战。选中地点按线上位置表单字段提交，保留一次 POST 后只读核验；补齐 preSign 来源页与异步请求标头，不填充反模拟检测证明或随机坐标。提交后的网络不确定性保持 unknown，只有独立状态查询确认才能显示成功。

协议事实继续仅参考本地 Quasar-core，独立实现，不复制 GPL 地点表、设备算法或验证码求解。没有新增依赖。页面不预加载签到，不自动提交、不重试，不改变独立服务账号与学校会话的边界。

## 验证和回滚

合成测试覆盖版本化参数、坐标有限值/范围/未知键、位置要求及前后要求变化、请求头、一次提交、过期 QR、状态核验与原因；真实 QuickJS 验证新包。原生矩阵覆盖保存/编辑/删除/选择/取消、旧包隐藏、非提交操作零签到请求、失败原因、窄屏及中英文。地点存储覆盖 Profile/学校/来源隔离、旧包拒绝、凭据不可见及未登录不变。

回滚可禁用/卸载社区包并恢复旧版客户端；已保存地点为宿主保留数据，旧宿主不会将其作为脚本凭据。新包经用户检查新 digest 后执行；真实活动签到结果和人工核心/网络审阅单独记录，自动回归不代替现场验收。
