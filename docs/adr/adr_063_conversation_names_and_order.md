# ADR-063 · 群名称补全与有内容会话优先

- 日期：2026-11-02
- 状态：Accepted（所有者要求完善超星群名并优先排列有内容群组）
- 承接：ADR-061。

`messages.conversations` 升为 1.1，保留 1.0 schema 和旧包校验；新增可选 `hasContent`、`lastMessageAt`。前者仅表示服务端或已加载本地记录确认存在可显示消息，不是未读；缺失为未知，不把未查询的群推断为空。后者是已知内容消息的源站时间，不能使用群资料更新时间或本地抓取时刻替代。参数仍为 1.0，SDK 不变，社区包升 0.3.1。

脚本从已加入群目录取身份；批量查询固定 Easemob 群详情补齐显示名，只接受当前目录内相同 ID 的结果。服务端最近会话接口只补已发现会话的内容/时间，不把协议回执、命令或陌生返回当作普通群消息。可选补全失败保留目录及已有名称；认证失效仍停止。查询有固定页数、条数和每批上限，不遍历每个群的历史，不从服务端返回任意 URL 发起请求。

核心保留已经取得的有效群名，避免后续仅 ID 的返回覆盖它；合并远端内容标记与 SQLite 中未撤回的规范消息。有内容的会话优先，其内按已知最新消息时间降序，其他会话保持稳定次序；群聊/私聊、来源和账号仍独立，离线采用相同排序。作业/课程/任务继续仅为不可点击摘要。

协议事实核对 [Easemob Web SDK 4.12.0](https://www.npmjs.com/package/easemob-websdk/v/4.12.0) 发布内容的 `getGroupInfo`、`getServerConversations`（ISC）及[官方消息文档](https://docs-im.easemob.com/ccim/web/message3)，不集成或复制 SDK。合成测试覆盖名称缺失、批量混入错误 ID、大整数、命令/回执过滤、未知与空的区分、部分失败、本地合并和重启排序；真实账号另行验收。
