# ADR-036：一卡通账户查询与可选卡号

- **Decision**：Accepted（2026-10-30；所有者本轮明确确认未提供卡号时取消强制手填；不等于人工安全签收）
- **范围**：`card.balance` / `card.transactions` 输出、生成类型和固定一卡通卡片；不改变认证、学校隔离、网络授权或写操作能力。
- **依据**：ADR-001 §3.4/§7、ADR-034 §3–§6；AGENTS 红线 #1/#3/#6/#8。

## 1. 问题与证据

参考 `traintime_pda` 固定提交 `e780e4d0` 的 `school_card_session.dart`：账户余额通过已认证 openid 请求 `myaccount/openMyAccount`，读取首个 li 的第二个元素子项中的第二个元素；流水通过 openid 和日期窗口读取 `queryCardSelfTradeList`。这两个读取不要求用户提供卡号，也不返回一个必须可用的卡号。

elecon 当前两个输出 schema 都将 `cardNumber` 必填；即使余额/流水成功，学校脚本仍会报缺卡号并让用户补填。这不是学校接口的必需输入。不得用学号、openid、固定占位或空字符串伪装卡号。

## 2. 决策行为

1. 两个输出的 `cardNumber` 改为可选：缺失明确表示学校未提供真实卡号。已经有卡号的输出继续按原字段携带，不改其含义。
2. 余额与交易的金额、币种、交易时间和方向等既有要求保持；卡号缺失不能降低业务数据验证，也不代表多张卡已合并。
3. 客户端固定一卡通卡片在缺卡号时显示“校园卡账户”，直接显示已验证余额/流水。已有卡号仅显示末四位；不把学校返回的 masked 字段当作完整卡号。
4. 西电脚本按 PDA 已见证的账户接口读取，优先使用学校明确标注的卡号或用户已配置的真实卡号；没有卡号则省略该字段，不再强制手填。没有证据的多卡选择接口不臆造，不按页面里任意数字推断卡号。
5. 本变更不提供支付、挂失、换卡、充值或任何物理副作用能力。

## 3. 版本与兼容

依据 ADR-001 §8 与 AGENTS 红线 #6 的公测前约定，本次为预览契约的显式破坏性更正，暂保留当前 1.0 编号；不为本功能扩张通用 schema 历史版本或代码生成机制。两个输出移除 cardNumber 的 required，但有真实卡号的旧输出仍全部有效。旧 V1 签名包和已批准源码不改字节，不修改其认证或权限门。

生成 Dart/TS 类型将卡号设为可选，下游调用点显式处理缺失。schema、生成类型、解码器、固定卡片、回归与 contract changelog 同批更新；本轮连同 ADR-037，客户端升至 0.3.0+6，学校源码升至 0.12.0 并重新确认 digest。先更新客户端再安装新源码；旧客户端仍按旧 schema 拒绝缺卡号的新输出，不能声称支持这种组合。公测前稳定版本和历史多版本机制另行决定。

## 4. 验证与人工审阅

覆盖有/无卡号余额及流水、空串/伪造标识拒绝、真实 first-li 布局的合成金额、openid 过期刷新和认证失败、SDK 包版本门、生成类型和 UI 显示、已有带卡号输出回归，以及未更新旧客户端不兼容的边界说明。夹具全部合成。此 ADR 的接受不等于真实账号/平台或人工安全签收。
