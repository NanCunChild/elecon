# ADR-046 受信脚本统一请求与按钮触发控制

- **Decision**：Accepted（2026-11-01，所有者明确废除 action 方案，要求空调按钮触发一次控制请求、随后查询状态，签到使用通用请求）。
- **Landing**：已实现；隔离副本 316 项 Flutter 回归及相关协议/工具检查通过，剩余验收见受信脚本计划。
- **覆盖**：ADR-040 的专用 action/grant、额外确认和单请求宿主作用域；ADR-045 的 action scope 限制；AGENTS B6 对新源码额外命令确认的要求。V1 兼容门不变。
- **人工审阅**：仍需人工核心/网络审阅；不代表真实设备或学校验收。

## 决策

新受信脚本统一经普通 capability 调用和 `ctx.fetch` 执行业务请求。移除 `manifest.actions`、ScriptActionScope、核心中的空调授权/准备/执行入口及额外确认弹窗。学校端点、请求体、认证、签名和成功条件继续留在脚本；核心不新增签到专用执行通道。

空调页面的一次按钮/控件事件产生一次 `climate.command` 调用。西电脚本校验绑定设备与完整目标参数后只执行一次控制 POST，明确禁止重定向和自动重发；控制调用结束后，页面独立调用一次 `climate.status` 同步实际状态。控制失败、超时或未知也不重发，状态查询失败显示未知。页面执行期间禁用重复操作，不乐观修改设备状态。切身份、更新、离页或调用失效后不继续发查询或应用迟到结果。

查询和命令仍有不同业务含义：命令不加入 home 缓存/预加载，不在读取失败时自动回退、重登或重跑。一次发送是具体空调实现的行为约定，由真实模块和合成网络回归验证；宿主不宣称可通过通用 fetch 判定每个请求的远端副作用或提供服务器端 exactly-once。现有身份、安装 digest、网络范围、预算、取消与输出校验继续适用。

空调页面保持当前 Android 产品范围；SDK 的通用请求接口没有新增业务平台门。旧 V1 `climate.command` 不开放，既有 Broker/Masker/签名与控制边界照常维护。

签到协议可以直接使用脚本内通用请求，扫码是输入采集。没有“必须先接 action”的前置；本轮不实现 Chaoxing 登录、位置表、配置解析或真实签到，也不把任意脚本请求包装成签到验收。

## 版本与迁移

这是开发阶段的显式破坏性契约更新：新包的 manifest 不再接受 `actions`，工具链与公共解析器明确拒绝，而非静默忽略。包格式仍为 `elecon-script/1`；各已支持 SDK 的其它 API 与领域数据结构不变，不引入新 action SDK。西电本科包提升到 0.15.0，移除 actions 后由用户重新确认 digest；研究生包不增加控制能力。

恢复已有安装记录时，仅为保留来源、版本和原授权 digest 读取旧 action 包，将其标为需要更新，拒绝执行且不作为 provider。原始包字节与 digest 不改写；不能因一份旧包失效清空其它安装或自动退回 V1。用户显式导入更高版本的无 actions 包后恢复使用。该恢复路径不接受新安装，不构成另一条执行通道。

## 验证与回滚

验证 Dart/TS 双端拒绝 actions、普通 command 准入、旧安装保留及更新、运行前拒绝旧包、真实 QuickJS 的单次 POST、错误/超时不重发、按钮触发后单次查询、执行中重复点击、离页/退出/更新后的结果失效及状态未知。保留学校身份、网络与 V1 回归。

回滚必须同时恢复宿主、契约与包版本策略；不能用旧版本号覆盖新源码，也不能将移除字段后的包暗改回有 actions 的内容。真实设备、相机与学校验收另行记录。
