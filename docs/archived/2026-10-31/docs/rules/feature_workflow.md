# 规则 · 新功能工作流

> 2026-10-29 路线覆盖：新 `elecon-script/1` 路径遵循 [ADR-034](../../../../adr/adr_034_trusted_school_scripts.md)；允许用户授权的未签名侧载和当前学校凭据直接访问。V1 专属 official/Masker/双跑门不适用于新路径；身份隔离、背景执行、脱敏夹具和人工合并审阅仍适用。

配合 [`AGENTS.md`](../../AGENTS.pre-2026-10-31.md) 阅读。核心是一个**判定闸门**：先判断改动"碰不碰承重墙"，再决定走快车道还是慢车道。

---

## 1. 判定闸门（动手前先问）

> **这个改动涉及契约（`contract/`）或红线（核心/凭证/传输/签名）吗？**

- **不涉及** → 快车道（多数 adapter、UI 卡片属此）。
- **涉及** → 慢车道：先确认已有 ADR 是否覆盖；没有对应决策时先写 ADR，再实现。已授权的 ADR-034 实施无需为每个步骤重复开决策。

---

## 2. 快车道（adapter / UI 卡片等）

适用：新增/修复某学校 adapter 或受信源码脚本，以及新增一种标准 schema 已支持的 UI 卡片。新脚本可在既定 SDK 中处理认证、校本计算和 DOM，不因读取其授权身份凭据而自动升级为核心改动。

```
Issue → adapter/ 或 feat/ 分支 → 实现（限定在声明范围内）→ 夹具+测试 → PR（1 人审）→ 合并
```

- adapter 改动天然隔离、可热替换，审查轻、迭代快。
- 但凡需要新的 schema 字段、新的核心能力 → 立即升级为慢车道。

---

## 3. 慢车道（涉及契约 / 核心 / 传输 / 签名）

```
Issue → ADR（adr_00X）→ 评审通过 → feat/ 分支 → 实现 → 测试（含安全用例）
      → PR（声明遵循的 ADR + 红线自检 + 至少 1 人工审阅）→ 合并
```

- 改 `contract/schema` 或 `manifest` 规范：默认向后兼容；破坏性变更需在 ADR 写明迁移方案与版本策略。
- 改核心/broker/凭证/传输/签名：附安全用例，人工审阅不可省。

---

## 4. 范围纪律（对人也对 AI）

- **不扩张范围**：发现已有决策未覆盖的核心/契约变化时先起草 ADR；已有 ADR 覆盖的实现按批准范围推进，不顺手扩大范围（红线 #10）。
- **不顺手加依赖**：新依赖单独提出、声明许可证；GPL 系先确认边界隔离方案（红线 #9）。
- **不静默改契约**：契约改动永远显式、永远走 ADR。

---

## 5. 典型路径对照

| 目标功能 | 车道 | 是否需要 ADR |
|---|---|---|
| 适配某学校新接口 | 快 | 否 |
| 加一个"成绩卡"的展示变体（schema 已够） | 快 | 否 |
| 新增"宿舍水电"数据类型（schema 要加字段） | 慢 | 是（改 contract） |
| 接入一种新的传输底座 | 慢 | 是 |
| 调整插件签名/吊销机制 | 慢 | 是 |
| 给 adapter 增加一种新的核心能力（如 broker 新方法） | 慢 | 是（改 adapter-sdk 契约） |
