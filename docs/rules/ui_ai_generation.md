# 规则 客户端页面与模板

依据 [ADR-041](../adr/adr_041_current_architecture.md)，后续组合提案见 [ADR-042](../adr/adr_042_providers_pages_enhancements.md)。旧卡片中心规则已[废弃归档](../archived/2026-10-31/docs/rules/ui_ai_generation.md)。

## 职责

原生页面、路由、布局与交互由 Flutter 客户端实现；脚本提供标准业务数据，不下发 Flutter Widget tree。ADR-080 已接受网页内作者 JS 自绘交互，按独立生命周期分片实施，实际支持范围见现行架构与实施计划。独立课表、图书查阅和论坛可以组合多个能力，不受“一 schema 一首页卡片”限制。首页摘要与完整页面应共享查询和领域模型，避免在两处复制认证、缓存和数据转换。

模板是客户端固定组件的复用：分页列表、详情、筛选、时间网格和 generic 展示可按实际需要组合。论坛线程不能直接改名为 notice，个人借阅不能充当书目检索；标准数据不够时先写领域 ADR。来源与绑定页面使用 ADR-066/086 已实施的版本化字段；其他 Proposed 扩展不凭规划文档加入现有包。

## 输入与呈现

- 按 schema 使用字段和单位；不以假空集合表示失败，不把未知状态改成 false/0。
- 保留来源、实体 ID、分页、时间与 stale/partial 信息。列表进入详情使用同一数据来源；不能点击后重新选择提供者。
- 颜色、间距、字号使用主题 token，覆盖深浅色及无障碍；文案使用 zh/en arb。版本号与官方链接等事实集中配置。
- 查询异步并处理 loading/error/empty/stale；新源码按 ADR-046 由明确用户操作触发普通请求，无额外 action 或逐次确认门。展示、预加载和缓存恢复不触发命令，未知结果不自动重发；V1 保留其兼容确认门。
- UI 不获得完整凭据库、主密钥或未净化诊断；宿主标准输出校验不是对受信脚本的通用防泄漏系统。
- 安装检查、脚本工作台、浏览器和固定输入表单按 ADR-034/037/039；学校认证流程留在脚本。

## 验证

对实质交互变化验证标准输出到组件、分页/筛选状态、页面离开与切身份取消、来源绑定、失败恢复和适用命令门。布局或文案小改按影响验证，不为机械覆盖重复实现逻辑。新增权限/契约先开 ADR；已有标准数据的独立页面不强制新建 schema。
