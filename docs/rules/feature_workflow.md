# 规则 功能工作流

依据 [AGENTS](../../AGENTS.md)与 [ADR-041](../adr/adr_041_current_architecture.md)。旧规则已[废弃归档](../archived/2026-10-31/docs/rules/feature_workflow.md)。

## 按变化范围选路径

| 变化 | 流程 |
|---|---|
| 已有 SDK 内的学校认证/归一化、已有 schema 的页面或模板 | 范围确认 → 实现 → 相关夹具/widget 回归 → PR 审查 |
| contract、核心抽象、新授权、传输、控制命令 | 已有 ADR 覆盖则按其实施；否则先起草 ADR，明确状态/迁移/验证，再按授权推进 |
| 文档重新规划、方案研究、代码审计 | 标明事实与提案 → 检查引用和范围 → 分步文档提交 |
| V1 兼容修复/删除 | 查[兼容边界](../reference/legacy_compatibility.md)，验证旧使用者和退役前置 |

当前开发阶段允许有迁移计划的破坏性契约更新；更改字段含义必须升版本，保留旧版本或给出明确拒绝/迁移，不以开放 JSON 字段掩盖语义破坏。

独立页面不必新建 schema：若已有标准数据足够，可复用查询与领域模型。图书检索不等于个人借阅、论坛不等于通知；语义不同才新增契约。新增权限、远端控制或任意脚本组合不能当作普通 UI 重构。

## 每个切片交付

明确问题、受影响的消费者、回滚方式、实际验证与剩余验收。契约同时更新 registry/schema/SDK/生成物/消费端/CHANGELOG。核心和安全敏感路径经人工实质审阅后合并，不能拿自动测试替代。生产部署或发布作为明确任务执行，研究方案不代表已经上线。
