# 西电 SDK 4/5 脚本

版本：本科包 `0.20.1 / SDK 5`，研究生包 `0.20.1 / SDK 4`；客户端本地构建基线 `0.7.0+10`。依 ADR-046 移除 actions，控制沿用普通 capability 与 ctx.fetch；保留既有凭据、输入、浏览器与首页缓存。参考本机 `traintime_pda` 提交 `e780e4d01ea740c979ff5c31b9db439dbc586864`（2026-10-14），2026-10-31 只读核对水电及空调相关源码；源码适配和合成回归不等于真实学校/设备验收或人工安全签收。

本科和研究生是两个学校身份：`xidian_undergraduate`、`xidian_postgraduate`。教务路由由安装的学校包绑定，不再由共享 IDS 记录中的 `role` 决定。

旧西电源码还在 `adapters.pin` 指向的外部仓，签名包仍在 bootstrap。本目录更新的是新的受信脚本路径，不修改旧路径缓存、外部仓 pin 或签名内字节。导入后须选择对应的本科/研究生学校；原 `xidian` 是保留的旧身份，其凭据不会自动迁入新学校。

## 0.20.1：图书认证入口

图书登录直接打开超星官方 CAS 初始化入口，由原站设置 `firstReferer` 并跳转 IDS 的 `/cas/index` 回调，不再把初始化入口本身当作 IDS service。2026-11-02 未认证公开页面检查证实该初始化顺序；真机 0.20.0 曾跳到未声明的 `https://i.chaoxing.com`，本次仍保持现有网络范围，未授权该个人空间。合成回归覆盖入口、原站中间页与稳定 OPAC JWT 保存，实际 QuickJS 回归覆盖入口及取消后不保存会话。

同日已在授权的本科 Android 设备上通过应用内确认安装 0.20.1，图书认证到达 `https://mfindxidian.libsp.cn`，借阅查询正常完成并显示更新时间，原异常跳转未再出现。此记录仅证明该本科现场链路，不含学生数据或借阅数量；研究生、其它账号与平台未测，核心人工安全审阅仍单独完成。

## 0.20.0：待完善信息

宿舍空调未绑定设备时通过标准 `configuration_required` 表达待完善信息，客户端整体刷新跳过已知缺配查询；点击「完善信息」才填写设备信息。已有设备的网络/解析失败继续显示请求失败。新语义需 ADR-059 客户端支持，旧宿主不认识错误码时保持失败，不伪造成功或空设备列表。

## 0.19.0：整学期缓存

课表声明 `schedule.week` 1.2，一次整学期请求返回 `termWeeks` 详情；宿主本地切周复用原始取得时间，过期后台刷新期间继续查看。旧版本仍按逐周缓存处理。更新宿主后检查并确认新包。

## 0.18.1：旧会话与登录等待修复

学校脚本忽略旧会话内超出服务站点范围的 Cookie（例如 `Domain=edu.cn`），防止 Android 拒绝恢复 Cookie 导致登录提前退出；不删除学校会话，仍需原站认证核验。原站页面跳转时在脚本侧等待后再检查，避免瞬间耗尽睿思登录重试。

## 0.18.0：独立睿思账号

按 [ADR-052](../../docs/adr/adr_052_community_accounts_and_chaoxing.md) 新增 `forum.session` 与 `https://rs.xidian.edu.cn`。基本包升级后重新检查授权，论坛 Tab 显示账号连接页；原生表单使用睿思自己的用户名/密码，遇验证码转到原站页面。表单参考 traintime_pda 同一提交的 `lib/external/ruisi_flutter`（BSD-3-Clause），版权与完整许可证保留于源码及 [RUISI-LICENSE.txt](RUISI-LICENSE.txt)，随内置包分发。

会话独立存于当前 Profile/学校的 `xidian.services` / `xidian.ruisi`，不写入或复用 IDS 密码。登录须由“当前用户”页头和退出控件核验远端 UID；只保存 Cookie，不保存密码或密码摘要。本地退出只删除睿思会话，不等于远端注销。`forum.session` 的参数为 `operation: status|login|logout`，默认 status；不允许首页缓存或后台执行。帖子浏览尚未实现。

无可执行论坛/消息来源时核心隐藏对应 Tab。论坛登录、取消和失败不改变学校登录与课表。

`classroom_directory.js` 内置 2026-11-01 经已授权手机 E-Hall 查询核实的 36 个教学楼名称/代码/校区（N/S 保留来源代码）。这里只保存公共楼宇目录，不含个人数据或设备标识；`classroom.buildings` 不读凭据、不登录、不请求学校，目录变化随脚本更新。按楼名或代码查询占用均复用此目录，不再调用 `jxlcx.do`；占用数据仍实时请求学校。真机字段形态核对发现学校的空节次是完整 `JC1–JC11` 键下的显式 `null`；按 PDA 的既有占用判定将显式空值处理为无占用，真正缺键仍为未知。此为字段解析修复，不代表现场验证教室实际空置。

一卡通消费图由客户端核心按已有标准流水计算，非西电专用能力：支持近 7/30/90 天、商户分布和每日变化；只统计已加载记录，并标明分页未完整、日期时区和币种，不把充值/退款算消费。无流水能力或没有可统计消费时不显示图。

## 0.15.0 本科：宿舍水电与空调（客户端 0.5.0+8 / SDK 5）

依据已确认的 ADR-040，本科统一包新增 `energy.meters`、`energy.usage@1.1`、`climate.devices`、`climate.status` 和独立 `climate.command`。先升级客户端，再在应用中确认本科 0.15.0 源码及新增的 `https://ignypt.xidian.edu.cn`、`https://gxkt.juhaolian.cn` 网络范围和控制能力。研究生仅因共享会话代码更新至 0.13.1 / SDK 4，不包含水电或空调能力。

- **水电**：在首页“宿舍水电”连接校园网查询；复用当前本科身份的已验证 IDS，独立执行水电 OAuth、逐请求签名及 AES 编码。首次缺学号时由脚本请求。选择返回的实际水表/电表后查看历史，可选日期窗口；默认电表近一个日历月、水表近一年。剩余电量与累计读数、上次读数、用量分别显示，不把余量冒充累计读数。多表不按首条默认选择。列表/历史按实际成功时间缓存，失败保留有时间标注的旧值。
- **空调**：在首页“宿舍空调”绑定自己有权控制的 15 位 IMEI 和设备名称，状态验证成功后仅保存于当前学校身份。可更换绑定；不扫描或猜测其它房间的设备，不编造 token 登录或账户设备列表。设备 `electricAmount` 的剩余/累计语义尚无证据，本版不作为剩余电量展示。
- **控制**：Android 提供开关、18–32℃、模式、风速、扫风、强力和辅热。按钮或控件事件直接触发一次普通请求，不另弹确认；模式/关机等仍按设备声明生成温度、风速、强力、辅热及清洁状态的完整联动目标。只发送一次 POST，不自动重试、重登或跟随重定向；随后独立查询一次实际状态。界面不提前切到目标值，失败/未知不会伪报已生效。其它平台的空调页面暂只提供状态查看。
- **状态与取消**：进入/恢复可见时做只读同步；没有常驻状态轮询或后台命令。状态失败保持未知并禁用控制。切校、登出、禁用、更新、离开页面、退至后台或取消会使未完成调用失效；已经发出的远程操作无法回滚。

工作台可直接运行只读水电和状态能力，例如 `energy.usage` 参数 `{"meterId":"从本人账户发现的实际表标识","from":"2026-10-01T00:00:00+08:00","to":"2026-10-31T23:59:59+08:00"}`。`climate.status` 使用当前身份已绑定的 deviceId。工作台显式调用也使用同一普通 `climate.command` 能力；它不会自动查询状态，调用者需要随后显式调用 `climate.status`。命令禁止进入首页缓存或预加载。

来源新增 PDA `ids_session/energy_session.dart`、`miscellaneous_session/aircon_session.dart`、`model/aircon_state.dart`、`page/energy/aircon_remote_page.dart` 与抄表模型/水电卡片，参考提交仍为 e780e4d01ea740c979ff5c31b9db439dbc586864；保留 MPL-2.0 版权。学校 AES 实现为本目录 MPL-2.0 JS，以独立向量/Node OpenSSL 解密和真实 QuickJS 验证，无新依赖、原生加密权限或密码协议。

本轮合成回归不访问学校和真实设备；校园网、实际响应与用户选定设备的真机验收、核心人工安全审阅仍须单独完成。新版源码安装授权仍由用户在应用内确认，不能直接覆盖已批准 digest。

## 0.13.0 首页与登录更新

IDS 认证通过后显示宿主固定“正在登录”遮罩，阻止页面误触；完整 Cookie 集合在至少 250ms 的两次采样中稳定后保存，继续业务验证再返回。Cookie 旋转会继续有限采样，取消按钮保持可用。此窗口是采样间隔，不代表真实学校网络总耗时。

`manifest.home` 声明缓存时效与自动加载内容：公告15分钟、校历1小时、当前周课表15分钟、余额2分钟、成绩1小时、考试/借阅30分钟。登录后、首页进入或恢复前台会静默刷新到期项目，手动刷新可强制更新；不弹登录/补填界面，失败保留旧值和时间。流水、教学楼/空教室及公告正文仅按需取数并缓存。无参 `schedule.week` 由脚本解析当前校历周，宿主不推算西电周次。

缓存按当前学校身份、源码 digest 与查询参数隔离，显示实际成功取数时间；超过7天不展示。持久化随已有H/S/M选择，内存档重启不保留。登出删除当前身份数据。升级需先安装新版客户端，再确认两个学校源码包各自的新 digest；不自动替换旧授权。

公告标题不再包含嵌套日期；点击后通过现有 `notice.detail` 拉取纯文本正文，保留段落、表格分隔和附件名。图片公告若无文字则说明缺少文字正文；附件仍只展示名称。

## 构建与导入

在仓库根目录执行：

```sh
npm ci
npm run scripts:xidian -w tools
```

生成：

- `dist/school-xidian-undergraduate.elecon.json`：本科统一包，SDK 5、21 个能力（含同包登录）。
- `dist/school-xidian-postgraduate.elecon.json`：研究生统一包，SDK 4、16 个能力（含同包登录）。

也可传 `-- --out-dir /tmp/xidian-scripts`。构建器先编译、校验两个统一包，不执行学校代码、不签名，并清理输出目录内旧的未分校包和独立登录包。所有本地模块合并成一个 ESM，`elecon:html` 保留为宿主内置模块。输出保留 MPL 版权和来源说明。内置选校展示该学校统一包的源码、身份与权限并确认。

同步应用内置资源（需提交生成的 JSON、README 与 MPL 全文；smoke 会校验源码与内置包一致）：

```sh
npm run scripts:xidian -w tools -- --out-dir client/assets/school-scripts
```

每校只安装一个包：公开通知和有效会话查询直接走 HTTP，不创建浏览器或独占租约；私密能力缺少/失效会话时由同包登录流程打开官方页面，验证保存后接着完成原查询。每个目标最多重登一次，取消、输入错误与业务解析错误不会触发反复登录。Windows/Linux 可以使用不需要登录页面的请求；可见浏览器桥仍只支持 Android/iOS/macOS。

从分包版迁移：内置选择确认统一包 `0.8.0` 后，移除当前学校旧的 `*-login` 安装记录，保留 `xidian.auth` 凭据；另一个学校不受影响。从文件更新时可手动卸载旧登录包。

## 首次使用

1. 在首次选校页选择“西安电子科技大学（本科生）”或“西安电子科技大学（研究生）”，或在设置 → 学校脚本的“应用自带脚本”中选择对应身份。查看并确认统一包源码、身份与权限后安装并切校，无需另找 JSON 文件。仍支持导入独立更新包。两套均可安装；新旧包 id 不同，应按需要手动禁用旧 `school-xidian` / `school-xidian-login`，不会自动覆盖或搬运旧身份凭据。
2. 直接在首页查看成绩、课表等信息；缺少有效会话时会打开该学校认证页，完成后继续原查询。仍可在统一包中运行 `generic.section` 主动登录，或传入自己的学号；学校认证页输入的数字学号也可在目标系统验证成功后存入当前学校会话，不放进运行结果：

   ```json
   {"studentId":"你的真实学号"}
   ```

   本科默认 `ehall`，研究生默认 `yjspt`；两校均可显式选 `system:"card"` 或 `"library"`。研究生查询公共教室时可额外登录 `ehall`，其教务路由仍保持 YJSPT。本科包拒绝登录 `yjspt`。密码、滑块、短信或企业微信二次认证在学校自己的可见页面完成。IDS Cookie 仅在当前学校内用于其它目标的 SSO，服务票据始终按目标重新取得，不复用一次性 ST。
3. 运行同包能力，例如课表 `{"week":3}`，成绩/考试 `{"term":"2026-2027-1"}`。不需要 `role` 参数；传入与当前学校冲突的角色会在任何请求之前被拒绝。学号优先使用显式参数或对应业务会话，不从另一学校或旧 `xidian` 身份猜测。
4. 校园卡查询会按需登录 `card`。账户页没有明确卡号时直接显示校园卡账户余额/流水，不再强制手填；已有真实卡号仍可携带并仅显示末四位，不能用学号、openid 或占位值替代。
5. 新图书馆查询会按需登录 `library`；同包从实际登录 URL/Cookie 取得的 JWT 和 groupCode 查询借阅。没有借阅的有效响应返回空列表，认证失败或分页不完整会报错。

每校仍只有一个当前账号身份；更换账号请先登出，避免把两个账号的业务会话混在一起。切校保留凭据，登出清除当前学校所有命名空间。这里不提供真实账号数据、默认密码或真实 openid。

## 能力范围

| 能力 | 本轮行为 | 保留的限制 |
|---|---|---|
| `notice.list` | 主动获取教务处 HTML，使用内置 HTML parser | 仅首页，未伪造更多分页 |
| `schedule.week` | 本科 `SKZC` / 研究生 `ZCBH` 位图；本科调停补课、部分节次变更；实际校历日期 | 未排课程没有周时段，暂不塞进周课表 |
| `grades.list` | 本科/研究生独立字段与等级成绩、0 分、重修来源；有界完整分页；按学期过滤 | 不猜 GPA/绩点换算；构成明细未建模 |
| `exam.list` | 本科安排及待安排、研究生发布过滤；中国墙钟转 UTC | 当前 schema 无结束时刻；待安排保持未知状态 |
| `classroom.buildings` / `classroom.available` | 内置楼宇目录、日期或周/星期、节次/时间窗口；缺键保持未知 | 目录离线可用，占用查询需 E-Hall 会话 |
| `faculty.search` | 官网姓名关键词/研究方向分页查询，纯文本简介与公开主页 | 无需登录，不抓取全站；仅用户触发 |
| `card.balance` | 明确余额标签及参考仓见证的首个 li 元素布局；精确整数分 | ADR-036 允许无卡号账户结果；未提供时省略字段，不猜测身份 |
| `card.transactions` | JSON `beginDate/endDate/tradeType/openid`、日期数组、本地分页；收入/支出与特殊类型 | 默认中国当地近 30 天；不把本地分页冒充服务端分页 |
| `library.loans` | 超星 CAS → 新 OPAC，JWT header/cookies、预热、groupCode、实际借阅字段和有界分页 | 不迁入旧 shuwo/openId 链，不自动续借，不为每本书扇出封面请求 |
| `term.list` | 返回来源明确提供的当前学期 | 未证实历史列表接口，不声称列全历史 |
| `calendar.academic` | 本科开始日期 / 研究生 `QSRQ` | 不猜结束日期、假期与教学周总数 |

参数继续使用既有标准字段；`studentId`、`cardNumber` 是该学校的可选配置，`role` 只能与包绑定角色一致。查询 `schedule.week` 可指定 `week`，缺省按学校校历取当前周；空教室需楼名/楼号及日期或周/星期。学校业务错误通过工作台的脱敏日志可见，顶层宿主失败码仍由 SDK 统一归一化。

## 会话与网络

同一学校的统一包使用 `xidian.auth` 命名空间，键为 `ids`、`ehall`、`yjspt`、`card`、`library`。SDK 2 的完整地址包含 `schoolId`，两校即使 namespace 和 key 相同也不会串用。每条是有版本的 JSON 会话：`{version:1,service,cookies,data,updatedAt}`；其中 `data` 保存真实来源的 openid/JWT/groupCode、明确提供的学号或卡号等。地址不因脚本升版改变。

以下为 `0.8.x` 浏览器路线历史记录；当前 `0.10.0` 路线见下节，`0.9.0` 协议模式仅保留实验代码。旧教务登录要求页面加载完成，且浏览器内只读当前学期接口返回有效业务 JSON；页面路径、HTTP 200 或 Cookie 出现本身不构成成功。业务页与 Cookie 快照须连续稳定至少 1.2 秒，写入前再检查页面。`0.8.5` 的 E-Hall 认证先独立验证、保存 IDS，再验证、保存业务会话；业务失败保留已验证的 IDS 与旧业务记录，未通过独立验证的 IDS/MFA 临时快照不写入。全程仍受约 100 秒 deadline / 宿主 120 秒总预算限制；长时间 MFA 可能超时，不能把超时当成功。

普通 JS 自行管理 Cookie、逐跳 HTTP 重定向和认证中间值。新 Cookie 在解析业务结果前保存；同名 Cookie 按 domain/path 区分；已知同一完整地址最后一条生效。校园卡 openid 按参考行为保留五分钟，查询认证失败最多刷新重试一次，不重试取消或输入错误。

`0.8.3` 按所有者要求进行原始 HTTP 链路拟真：网络清单显式声明 `http://ehall.xidian.edu.cn`，浏览器和脚本均撤回自动 HTTPS 替换。E-Hall 只在实际业务验证成功后保存页面 origin，Cookie 采集与后续查询沿用该协议；默认 IDS 认证入口仍为 HTTPS。其它站点和端口未放行，跨源敏感 POST 不重放。设置页登录直接运行同包认证；首页缺少实际卡号或学号时可补填后继续。新包需要确认网络范围后安装。

`0.8.4` 的 E-Hall 登录从学校 `/appShow` 入口开始，不再直接拼接 `IDS login?service=appShow`。2026-10-30 的未登录逐跳探测及独立 Chrome 表明，学校会先初始化 E-Hall 会话，再生成经过 `/login` 的嵌套 CAS service；其中会话路径和内层 service 必须由学校保留。沿用该原始跳转，不手工复制动态回调、改写协议或跳过业务 JSON 验证。研究生平台、校园卡和图书馆入口不变；研究生查询共用 E-Hall 教室时也使用此入口。该差异已复现，账号认证后的修复效果仍需真机验证。

`0.8.5` 按独立 Chrome 实验重现 E-Hall 流程：先打开 HTTPS 门户根入口，在 `/new/index_xd.html` 以只读接口确认 `hasLogin === true`；再打开无 service 的 HTTPS IDS `/authserver/login`，在个人中心确认账号设置接口的成功码与有效账号标识。此处只使用校方标识做页面内校验，不将账号设置或内部标识带回宿主。随后按五个实际认证/个人中心 URL 收集 IDS Cookie，快照稳定并复查后立即保存 `ids`，再打开 `/appShow`、验证学期并单独保存 `ehall`。后续业务阶段不再用未经 IDS 独立复查的新快照覆盖该 IDS 记录。

此分阶段路径适用于本科教务及研究生共用的 E-Hall 教室登录；研究生平台、校园卡和图书馆保留原入口，可复用同学校身份已经保存的 IDS 凭据。本科/研究生包都升版为 `0.8.5`，不增加域名、HTTP IDS 或宿主权限。分阶段路径共享最多 140 次轮询、五条等待日志；IDS 最多四轮、业务最多五轮 Cookie 采样，至少隔 750ms，稳定期仍为 1.2 秒。预算回归覆盖晚到成功及恢复/采样/日志，不超过宿主 256 次调用；其它路径保留最多 150 次轮询和六轮采样。

`0.8.6` 补充本轮 CPH2653 实测分支：手机在门户登录期间落到 IDS `/personalInfo/personalMobile/index.html`，`0.8.5` 因等待 E-Hall 回跳而超时。现在个人中心的桌面/移动两个明确路径均通过同一账号设置接口做独立验证；若门户阶段已落到经验证的 IDS 个人中心，则先完成无 service 的 IDS 验证与稳定保存，再使用同一浏览器会话重新打开 E-Hall 门户一次，确认 `hasLogin` 后继续业务。再次落到 IDS 不会无限重开，门户失败仍保留先前已验证的 IDS。

历史 `0.8.6` 版本：IDS 采样/恢复新增移动个人中心 URL，共六个 URL；分阶段轮询间隔改为 750ms，最多共享 135 次，仍受 100 秒 deadline 限制。IDS/业务最多四/五轮采样、五条等待日志不变；包括最多一次门户恢复，最坏宿主调用数不超过 254。旧未受影响入口保持原预算。新源码仍须确认安装，不新增网络权限或将 Cookie 存在直接当作认证成功。

Android 未提供 Cookie 属性时，快照只能绑定到采集的业务 URL。登录逐个真实 API 路径采样，空快照清除该路径已删除的旧值；服务器返回明确属性后会替换对应未知范围样本，避免旧值压过轮换值。这不能恢复平台根本未导出的完整 Cookie 库；同名 Cookie 真实路径不明时仍可能需要重新登录。

2026-10-30 未登录入口逐跳探测确认校园卡链路为 `v8scan.xidian.edu.cn → xxcapp.xidian.edu.cn → ids.xidian.edu.cn`；两校统一包和 HTTP 重定向列表均包含精确的 `https://xxcapp.xidian.edu.cn` origin。该探测未提交账号，不证明认证后全链路成功。

在“学校脚本”中运行统一包时，日志保留浏览器的 loading/ready/blocked 状态及 origin，并记录打开、已验证并保存阶段。被拒绝的页面只显示 scheme/host/port，不保存完整 URL、路径、query、fragment、票据或 Cookie；取消导航回调不会覆盖 blocked 原因。若是新的域名遗漏，以该 origin 和所选 system 定位后更新源码包并重新确认，不加通配白名单。

所有 origin 在 manifest 中精确声明。没有通配域名、公共代理、TLS 证书绕过或绕过登录的接口；当前宿主对声明浏览器的脚本最多允许 40 次 HTTP 请求、256 次调用、120 秒，分页均有上限，达到上限明确报错而非返回截断结果。

## 额外能力是否必要

ADR-037 提供有界原生输入，ADR-038/039 增加 SDK 4 首页声明与固定登录收尾遮罩，均不增加网络/凭据权限、认证 DSL、Masker或加密原语。公告正文复用既有 notice.detail capability。实际需求与后续建议见 [能力差异评估](../../docs/reference/xidian_script_update.md)。需要区分宿主 API、业务输出契约，以及平台/网络条件：卡号约束是契约缺口；长时间 MFA、可恢复浏览器身份是可选宿主改进；校园网可达性不是给脚本增加一个函数就能解决。

## 0.10.0：学校原页登录与会话收割

当前默认入口为 `login.js → webview_login.js`。本科、研究生及研究生共用 E-Hall 都先打开**无 service 的 HTTPS IDS 官方登录页**。账号密码、滑块、MFA 完全由学校页面处理；脚本只在用户填写时读取数字学号用于后续查询，不读取密码或验证码、不替换学校表单、不代提交主认证请求。

进入桌面或移动个人中心后，通过学校只读账号设置接口验证全局认证，等待页面及分路径 Cookie 快照稳定至少 1.2 秒，最后复查并独立保存 `ids`。没有有效页面验证时，即使出现 CASTGC 也不记为登录成功。收割使用现有六个认证/个人中心 URL，保留同名不同路径 Cookie。

之后以已收割的 IDS Cookie 执行独立的 CAS 服务签票及原生只读学期请求。WebView 保持在学校个人中心，**不打开 E-Hall 门户或教务应用 HTML**，避免把 `wdkb` 移动页面的“调用接口异常”作为登录页面显示。签票响应和 Cookie 本身都不代表业务可用，只有正确目标的正常学期 JSON 通过后才提交新业务会话；待验证 Cookie 仅在本轮内存保存，失败时保留旧业务记录与已验证 IDS，包括签票时轮换的 IDS Cookie。原始 HTTP E-Hall 跳转仍按实际 origin 使用，不套用 PDA 的 HTTPS 改写。

阶段日志为 `xidian_login_open:ids`、`xidian_login_saved:ids`、`xidian_login_exchange:<system>`、`xidian_login_probe:<system>`、`xidian_login_saved:<system>`。后两阶段失败不撤销 IDS 保存；服务再次要求密码/MFA 时明确失败，不自动切入账号密码代请求。校园卡/图书馆保留原学校页面路径。浏览器轮询/稳定性沿用既有有界实现，100 秒认证 deadline、宿主 120 秒及调用/请求预算继续有效。

`pda_login.js` / `pda_ui.js` 仅保留为独立协议实验及回归，默认分发包不包含该状态机、账号密码输入页或 AES 登录代码；没有运行参数可以切回它。后续原生登录界面在 WebView 实测验收后再接入。旧 `authFlow=pda` 会话仍可用于现有只读查询，主动重新登录将通过官方 WebView 建立新会话。两校新版源码与 digest 仍须由用户确认安装，不自动修改已批准的内容。合成与 QuickJS 回归不替代真机验证。本轮 CPH2653 本科官方页认证、IDS 收割、CAS 签票与学期 API 验证已实际通过（见[实施记录](../../docs/planning/trusted_scripts.md)）；研究生、其它系统和 Apple 平台仍需分别实测，人工安全审阅仍开放。

## 0.9.0：PDA 协议登录（历史实验，默认包已移除）

本科 E-Hall、研究生 YJSPT，以及研究生共用 E-Hall 的教室查询，改用 `pda_login.js` 的 HTTP 状态机：无 service 的 IDS GET → 表单解析 → AES-CBC/PKCS7 密码加密 → 稳定设备指纹注册 → 滑块获取与签名验证 → 密码 POST / continue → MFA → 无 service 的全局 IDS 重定向与 CASTGC 检查 → 独立 service 签票 → HTTP Location 链 → 原生学期 POST → 保存目标会话。已验证的 IDS 及之后的 Cookie 轮换独立保存，业务失败不覆盖旧目标会话。

HTTP 客户端采用 PDA `idsDio` 的桌面 UA、form-urlencoded、手动重定向和统一 CookieJar；不套用 PDA 中没有调用者的 `ehallDio` 额外请求头。PDA 模式及其保存的会话按参考实现将 Location 升为 HTTPS，保留显式端口并继续检查声明 origin。旧浏览器采集的 HTTP 会话仍沿用原协议，未改变宿主的全局 URL 规则。两校网络范围不扩大。

可见页面仅在需要输入时打开 IDS，显示明确标注 elecon 的账号、手动滑块、短信/企业微信和验证码界面。请求均由背景脚本经宿主直连学校；不从 WebView 导出 Cookie，不打开门户或课表 HTML 作为成功门。WebCrypto 完成与 PDA 相同的 AES 格式；密码及一次性验证码只在本轮内使用，不写凭据存储或业务输出。浏览器输入提交后清空，结果只取一次。稳定的 32 位大写 hex 设备指纹仅随已经验证的 IDS 会话保存在 `data.browserFingerprint`，成功后的登录和 MFA 复用它；首次认证失败不会产生单独的设备凭据记录。

本版选择 PDA 已支持的手动滑块模式，保留真实拖动轨迹及其间隔字段；不移植图像自动匹配。滑块最多三次、验证码最多三次；MFA 成功后重新请求当前 service 的 login，不复用旧票据。脚本 110 秒 deadline、135 次输入轮询；宿主仍有 120 秒、256 次调用、40 次 HTTP 请求上限，任一先到即失败。原生重定向至多 30 次，并受总请求数约束。校园卡和图书馆仍使用 `browser_login.js` 的原浏览器认证。

回归使用合成账号、Cookie、表单、滑块和 MFA 响应，并独立用 Node/OpenSSL 对比 AES 密文；真实 QuickJS 执行实际打包源码。合成测试与无账号浏览器输入验证不等同于手机真实登录通过或人工安全签收。更新仍需用户确认新版源码 digest；不自动替换已批准的旧脚本。
