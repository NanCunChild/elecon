`0.7.5 / SDK 20`，分别绑定 `xidian_undergraduate` 和 `xidian_postgraduate`。提供学习通账号登录/本地退出、群聊与私聊会话、历史分页、纯文本发送及扫码签到。安装授权、凭据、网络和取消边界见 [ADR-052](../../docs/adr/adr_052_community_accounts_and_chaoxing.md) 与 [ADR-061](../../docs/adr/adr_061_message_history_and_storage.md)。不覆盖基本包的教务登录和能力。manifest accounts 声明学习通账号、用途、登录说明及本包 account.session 状态与登录入口，导入后在设置查看；旧安装需用户重新批准更新。

## 0.6.0 群名称与头像

按 [ADR-098](../../docs/adr/adr_098_conversation_avatars.md) 补齐空白/`_<groupId>` 占位群名：取群主、管理员、成员的去重顺序，最多四个联系人名称；明确超过四人追加省略号。显式群名优先，资料失败保留有效群名或稳定 ID。群图像是相同顺序的最多四张成员头像拼图，不使用课程封面。

图片仅从新增声明的 `https://photo.chaoxing.com`、`https://p.ananas.chaoxing.com` 请求，不带 Cookie 或 IM token、不跟随重定向。优先 pic120，已知 HTTP 图片来源升级 HTTPS；其他来源省略。PNG/JPEG 每张至多16 KiB；每次至多64个群成员样本、500份资料、64张去重缩略图，全部头像 data URI 合计至多1 MiB，并发最多4。可选资料失败不清空会话；认证失效、取消或资源超限继续中止。生产端是否允许用户 token 查询管理员/成员、真实图片域和格式仍需学校验证。

原生会话列表和聊天标题展示头像，空缺/解码失败使用默认图标；缩略图进入同账号/批准来源的受保护消息归档，缺失保留、空数组清除。解码不用全局 ImageCache，离页释放。新版需重新批准网络和 digest；SDK/消息发送语义不变，没有新增依赖。

课表仍使用基本包教务来源；超星周接口的合成对比、数据完整性限制及有限真实测速方法见[研究记录](research/README.md)。

## 0.5.0 学习通知与消息权限

新增独立“学习通知”首页卡片，使用 `notice.list` 1.1。0.5.1 按[官方 PC 通知前端](https://notice.chaoxing.com/res/pc/template/notice/notice.util.js)的协议，向 `https://notice.chaoxing.com/pc/notice/getNoticeList` 发只读表单 POST，携带当前学习通 Cookie，查询收件通知（`type=2`）与当前上海年份。响应为根级 `status`、`topNotices`、`urgentNotices`、`notices.list`，实体按 `idCode/sendTag` 去重。列表正文转纯文本，供本地详情；不标记已读，不调用通知发送、回复或环信消息获取通知。

沿用标准一基 `page/size`，脚本内部使用 `lastGetId` 游标，单次最多 8 个列表请求；请求窗口上限 160 条，超过预算明确失败。首页默认第一页仅一次列表 POST。只根据 `lastPage` 的明确 0/1 或 boolean 判断是否有下一页，短页/空页不代表已结束；不输出猜测的总数、未读或不可续用的游标。首页保护缓存 300 秒。官方登录重定向映射为需登录，访问限制/风控/限流显示通用源站失败，不撤销有效账号；POST 不跟随重定向或自动重发。

0.5.0 参考 Quasar-core 的 `apis/notice/myNotices_v2` 在本次授权真机验证中返回源站 IP 访问限制，未进入列表解析。0.5.1 改用该服务正常登录网页自身的列表接口，网络 origin 不变；未扩大 Cookie 的域或路径，不修改服务访问控制。该次验证仅证明当前设备与已授权账号能够读取通知，不代表全部学校/账户验收。

`messages.history` / `messages.list` 1.1 将活动与指令区分为 `activity` / `command`；指令只显示固定标识，不暴露或执行远端 action。历史返回当前发言权限，核心未知/禁言时禁用发送并提示。每次真正发送之前脚本再次只读核验，避免沿用旧历史或本地缓存许可；权限不能确认时不会打开发送连接。

群权限依据 [Easemob 群详情](https://doc.easemob.com/document/server-side/group_obtain_detail.html) 的 `mute` / `disabled`，以及 Web SDK 4.12 的 `isInGroupMutelist`、`isInGroupAllowlist` 接口事实。个人查询返回明确 boolean；白名单响应必须匹配当前 `member` 及 boolean `white`。群主/管理员由服务自动加入白名单，个人禁言仍优先于豁免，见[官方成员管理说明](https://doc.easemob.com/document/ios/group_members.html)。缺失字段、权限限制、网络故障均保持 unknown；只有源站确认允许才可发送。列表不逐群扇出权限请求，核验发生在打开历史和点击发送时。

通知模块最初研究本地 Quasar-core `notice.go` 的协议事实；当前 PC 端点、参数、响应包装与实体去重规则另以官方前端 `notice.util.js`、`pull_notice.util.js` 核验。仅独立实现协议事实，不复制、翻译或打包官方前端代码。参考版本与 GPL 边界见下方来源说明；未复制 Go 代码或引入参考项目依赖。HTML 规范化复用已有 `elecon:html`，没有新增外部依赖。

## 使用与支持范围

这是用户自行获取、检查和导入的第三方社区包，客户端不内置产物或推荐入口。选择对应本科/研究生学校后，在“学校脚本”通过“从文件导入”检查源码、HTTP/浏览器 origins、WebSocket origin 和相机权限后安装。可自行构建 `.elecon.json`：

```sh
npm run scripts:chaoxing -w tools
```

输出在本目录 `dist/`，不加入应用资产。卸载/禁用后，如无其他可执行消息来源，消息 Tab 消失。

0.1.1 修复页面跳转时过快耗尽重试的问题。消息页先通过学习通原站登录，脚本核验 UID/TID/FID 后仅保存该服务 Cookie。不会读取或尝试学校密码，不把学习通 UID 当作学号。账号记录在当前 Profile/学校的 `xidian.services` namespace、`chaoxing` key；namespace 不是同校脚本间的权限隔离。切换账号先本地退出；本地退出不代表服务端注销其他设备。

0.3.1 的消息页先显示本机已加载会话，再在前台核验账号并读取群与联系人目录；点击会话读取最新历史，可继续向前分页、刷新及搜索已加载会话。保留发送者名称/ID、精确消息 ID、源站时间和撤回状态；回执不混入正文，不发送用户已读操作。作业、课程、任务、活动和附件只展示摘要，不可点击。未读数、附件下载/发送、自动轮询和后台监听尚未实现。

群名称先使用加入目录，再按固定 Easemob 群详情接口每批最多 50 个补全；补全失败保留有效名称，不让 ID 回退覆盖本机已有群名。补全端点的 403 按功能/权限不可用降级，保留已经成功取得的目录与账号；401 仍作为认证失效停止。通过有界服务端最近会话及本机未撤回消息确认有内容的群/会话优先，按已知最新消息时间排列；未读取的群保持未知，不推断为空或未读。最多读取 5 页最近会话，不逐群拉取历史。`messages.conversations` 使用 1.3；群目录权限默认未知，打开会话时核验个人禁言、群禁言与白名单。旧版本保留原数据读取语义，缺少权限不默认允许发送。

纯文本点击发送后只发一次；只有匹配服务器确认才显示已发送，确认丢失保留“结果未知”，手动刷新历史核对，不自动重发。发送成功后只读刷新一次。离页/后台/切身份取消在途请求并清除草稿；没有持久发件箱。

已加载记录由核心 SQLite 管理，按 Profile、学校、包 digest、服务账号和会话类型隔离；不是脚本凭据键或首页缓存。H/S 档沿用当前保护方式持久化，M 档只存内存。每来源/账号最多 4 MiB、2000 条消息和 500 个会话，保留最近 30 天内加载的记录；本机不代表完整历史。退出/失效账号或撤销/更新来源清除对应记录。离线时可看已加载记录；写入失败会提示，发送确认不因保存失败变成可自动重试的失败。

更新需要支持 ADR-061 的客户端，并重新检查新增 `https://a1-vip6.easemob.com`、`https://useryd.chaoxing.com` 网络范围。IM token 只发固定 Easemob 端点，不发送超星 Cookie；资料查询只用于显示名，不输出手机号、邮箱、头像鉴权地址。`messages.list` 1.1 仍保留最长 15 秒、最多 50 条的群消息窗口语义，不将其结果写入新历史库。

“扫码签到”登录后触发相机，严格接受固定超星扫码路径及活动 ID/enc。支持无额外挑战的 QR 活动，以及用户已选择地点的定位 QR 活动。两次查询都检查人脸、照片和验证码要求，未知要求保留为不支持。执行 analysis/preSign 后至多一次提交，再查状态；传输丢失不自动重发，无法核实时显示未知。协议客户端标识是脚本计算的字符串，不读取硬件标识或伪造当前位置。签到二维码不进入 params、日志或缓存；签退、纯定位活动、人脸和验证码续提不在本片范围。

0.2.0 按 [ADR-055](../../docs/adr/adr_055_checkin_locations_and_diagnostics.md) 使用 `attendance.checkin` 1.1：消息页提供最多 16 个可编辑地点按钮。名称、地址、经纬度由用户填写，坐标须来自签到服务使用的地点数据，不假定地图坐标系或自动转换。每次进入默认“不指定位置”，点击地点后用于下一次扫码；地点按 Profile、学校和来源分别保存。未填位置时，定位活动明确提示先选择地点。提交补齐来源页和异步请求头；二维码过期、位置未接受、人脸/验证码要求等显示固定诊断，日志只记录固定诊断字段。服务要求的反模拟检测或附加验证不伪造，实际是否接受仍由服务核验。

0.2.1 同时修复现行签到二维码附带 `DB_STRATEGY=PRIMARY_KEY&STRATEGY_PARA=id` 时被误判为非签到码的问题。这两个字段仅作为已识别的页面路由提示接受，不决定请求地址、不原样转发；脚本仍只使用校验过的活动 ID 与 enc，并拒绝重复或未知参数。过期二维码只可离线验证解析，不能作为现场签到成功证据。

## 0.2.1 签到探针与日志

使用支持 ADR-057 的新客户端，并重新导入/确认 0.2.1 社区包后，正常点击一次“扫码签到”即可采集探针，无需另发诊断请求，也不会重试签到。随后从签到卡片的日志图标，或“设置 → 运行时日志”进入，筛选“脚本探针”并复制可见日志。正式版只接收宿主验证后的 `probe/1` 有界字段；debug 日志另有 `checkin_probe` 固定事件说明。它们只留在本地环缓冲，重启后不保留，不自动上传。诊断失败不会改变提交或状态核验。

日志格式：`probe/1 stage=7 event=failed http=0 ms=246 flags=000000??`。`event` 为 begin/ok/failed/unknown/skipped；`http=0` 表示该事件没有 HTTP 状态，其余为实际响应状态；`ms` 为本次调用开始后的累计毫秒数，最大 120000。阶段表用于定位失败发生在提交前还是提交后，不能仅靠 HTTP 200 或阶段 ok 推断签到成功。等待网络、扫码前会先记 begin；若宿主因总超时或取消硬终止脚本，可能只有末尾 begin 而没有 failed，此时该阶段表示最后等待位置。

| stage | 阶段 |
|---|---|
| 1 | 校验输入/是否选择地点 |
| 2 | 核验学习通账号 |
| 3 | 扫码或取消 |
| 4 | 校验二维码格式 |
| 5 | 提交前查签到状态 |
| 6 | 获取活动与初次要求 |
| 7 | 获取班级/课程关联 |
| 8 | analysis 取握手码 |
| 9 | analysis2 核验握手 |
| 10 | preSign 加载来源页 |
| 11 | preSign 后查状态 |
| 12 | 再次核验活动与要求 |
| 13 | 唯一一次最终提交及响应分类 |
| 14 | 独立查询最终状态 |

`flags` 从左到右固定八位：**定位要求、人脸要求、验证码要求、照片要求、本次选了地点、已尝试最终 POST、独立确认已签到、最近正文的类型已识别**；`1`=是，`0`=否，`?`=未知。要求位只记录服务标志，不记录具体地点；可选照片字段未出现表示未声明照片要求。第六位为 1 而第七位不是 1 时仍可能已提交，不能自动重发。第八位仅表示识别出固定响应类别，不能当作成功证据；第七位为 1 才来自独立状态查询。

探针不输出用户/班级/活动 ID、QR/enc、Cookie/token、设备字段、坐标/地址、完整 URL、响应正文、正文长度或异常原文。缺失要求位继续显示未知并拒绝提交，不通过缺省为 0 来掩盖协议变化。提供日志时同时说明页面显示的固定失败原因；真实账号/活动可用性仍需现场验证。

## 0.7.5 成员取样与缺图重取

getUsers4C资料查询补齐官方客户端的随机nonce、Unix毫秒及inf_enc请求签名；固定协议常量不是用户IM token，不读取或模拟硬件标识。仅对原有已授权资料端点签名，继续使用当前学校学习通会话Cookie，表单仍只包含本人puid及有限成员tid。缺签名的HTTP200不再被误当作已经取得资料；协议事实与合成签名向量见研究记录。

群详情失败不再阻止成员取样。脚本按官方 Web SDK 的 `users?limit=4&joined_time=true` 读取有界样本，识别 owner/admin/member 及根级 cursor，保留大整数管理员 ID；不额外遍历全体成员或请求管理员列表。已取得的成员样本保留五分钟，缺图结果不阻止后续取图；小于等于 8,000 字符且含图片的完整补全可缓存，其他结果仅保留元数据及样本，总缓存仍限制 12,000 字符/128项。旧缓存版本不沿用。占位名称判断及旧有效名称兜底留在脚本，原生归档接受显式标题更新。

已知图片来源中的原 `psize` 参数替换为 `120_120c` 缩略图规格，不给未知 URL 增加参数、不扩大 origin；每张仍限16 KiB，PNG/JPEG校验与无凭据请求保持。图片按每会话先一张再补拼图的顺序分配可选额度。

真机多数图片入口返回302。按ADR-098修正，仅新增固定 `https://p.cldisk.com` 图片来源；更新必须重新检查网络范围并批准digest。图片请求保持manual模式，只显式跟随一次指向三个已声明图片origin的跳转，两个GET均不带Cookie/token、均计入额度；逐图片完成含跳转的请求，避免所有首跳先耗尽可选预算。未知来源、连续跳转、CDN拒绝或非法图片均省略，不伪造成功图片。

响应头限于PNG/JPEG且字节魔数也确认为PNG/JPEG时，按实际字节生成标准data URI类型，允许源站缩略图沿用了原图片MIME的情况；HTML、SVG或未知格式不因扩展名被接受。显式登录/本地退出清除脚本的成员与图片补全缓存。

正式版沿用 ADR-057 的本地探针，`ms=0` 表示未测量阶段耗时；不记录身份、群号、成员 ID、名称、URL 或正文：

| stage | 含义 | flags（其余位未知） |
|---|---|---|
| 17 | 学习通身份核验 HTTP | 无 |
| 18 | 群/联系人目录 HTTP | 无 |
| 19 | 群详情 HTTP/结构 | 数组、非空、ID匹配、有名称字段、有群主、有成员字段 |
| 20 | 管理员 HTTP（保留） | 无 |
| 21 | 成员 HTTP | 无 |
