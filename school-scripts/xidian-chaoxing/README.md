# 西电学习通增强包

`0.3.0 / SDK 9`，分别绑定 `xidian_undergraduate` 和 `xidian_postgraduate`。提供学习通账号登录/本地退出、群聊与私聊会话、历史分页、纯文本发送及扫码签到。安装授权、凭据、网络和取消边界见 [ADR-052](../../docs/adr/adr_052_community_accounts_and_chaoxing.md) 与 [ADR-061](../../docs/adr/adr_061_message_history_and_storage.md)。不覆盖基本包的教务登录和能力。

## 使用与支持范围

这是用户自行获取、检查和导入的第三方社区包，客户端不内置产物或推荐入口。选择对应本科/研究生学校后，在“学校脚本”通过“从文件导入”检查源码、HTTP/浏览器 origins、WebSocket origin 和相机权限后安装。可自行构建 `.elecon.json`：

```sh
npm run scripts:chaoxing -w tools
```

输出在本目录 `dist/`，不加入应用资产。卸载/禁用后，如无其他可执行消息来源，消息 Tab 消失。

0.1.1 修复页面跳转时过快耗尽重试的问题。消息页先通过学习通原站登录，脚本核验 UID/TID/FID 后仅保存该服务 Cookie。不会读取或尝试学校密码，不把学习通 UID 当作学号。账号记录在当前 Profile/学校的 `xidian.services` namespace、`chaoxing` key；namespace 不是同校脚本间的权限隔离。切换账号先本地退出；本地退出不代表服务端注销其他设备。

0.3.0 的消息页先显示本机已加载会话，再在前台核验账号并读取群与联系人目录；点击会话读取最新历史，可继续向前分页、刷新及搜索已加载会话。保留发送者名称/ID、精确消息 ID、源站时间和撤回状态；回执不混入正文，不发送用户已读操作。作业、课程、任务、活动和附件只展示摘要，不可点击。未读数、附件下载/发送、自动轮询和后台监听尚未实现。

纯文本点击发送后只发一次；只有匹配服务器确认才显示已发送，确认丢失保留“结果未知”，手动刷新历史核对，不自动重发。发送成功后只读刷新一次。离页/后台/切身份取消在途请求并清除草稿；没有持久发件箱。

已加载记录由核心 SQLite 管理，按 Profile、学校、包 digest、服务账号和会话类型隔离；不是脚本凭据键或首页缓存。H/S 档沿用当前保护方式持久化，M 档只存内存。每来源/账号最多 4 MiB、2000 条消息和 500 个会话，保留最近 30 天内加载的记录；本机不代表完整历史。退出/失效账号或撤销/更新来源清除对应记录。离线时可看已加载记录；写入失败会提示，发送确认不因保存失败变成可自动重试的失败。

更新需要支持 ADR-061 的客户端，并重新检查新增 `https://a1-vip6.easemob.com`、`https://useryd.chaoxing.com` 网络范围。IM token 只发固定 Easemob 端点，不发送超星 Cookie；资料查询只用于显示名，不输出手机号、邮箱、头像鉴权地址。旧 `messages.list` 1.0 仍保留最长 15 秒、最多 50 条的群消息窗口语义，不将其结果写入新历史库。

“扫码签到”登录后触发相机，严格接受固定超星扫码路径及活动 ID/enc。支持无额外挑战的 QR 活动，以及用户已选择地点的定位 QR 活动。两次查询都检查人脸、照片和验证码要求，未知要求保留为不支持。执行 analysis/preSign 后至多一次提交，再查状态；传输丢失不自动重发，无法核实时显示未知。协议客户端标识是脚本计算的字符串，不读取硬件标识或伪造当前位置。签到二维码不进入 params、日志或缓存；签退、纯定位活动、人脸和验证码续提不在本片范围。

0.2.0 按 [ADR-055](../../docs/adr/adr_055_checkin_locations_and_diagnostics.md) 使用 `attendance.checkin` 1.1：消息页提供最多 16 个可编辑地点按钮。名称、地址、经纬度由用户填写，坐标须来自签到服务使用的地点数据，不假定地图坐标系或自动转换。每次进入默认“不指定位置”，点击地点后用于下一次扫码；地点按 Profile、学校和来源分别保存。未填位置时，定位活动明确提示先选择地点。提交补齐来源页和异步请求头；二维码过期、位置未接受、人脸/验证码要求等显示固定诊断，日志只记录固定诊断字段。服务要求的反模拟检测或附加验证不伪造，实际是否接受仍由服务核验。

0.2.1 同时修复现行签到二维码附带 `DB_STRATEGY=PRIMARY_KEY&STRATEGY_PARA=id` 时被误判为非签到码的问题。这两个字段仅作为已识别的页面路由提示接受，不决定请求地址、不原样转发；脚本仍只使用校验过的活动 ID 与 enc，并拒绝重复或未知参数。过期二维码只可离线验证解析，不能作为现场签到成功证据。

## 0.2.1 签到探针与日志

使用支持 ADR-057 的新客户端，并重新导入/确认 0.2.1 社区包后，正常点击一次“扫码签到”即可采集探针，无需另发诊断请求，也不会重试签到。随后从签到卡片的日志图标，或“设置 → 运行时日志”进入，筛选“脚本探针”并复制可见日志。正式版只接收宿主验证后的 `probe/1` 有界字段；debug 日志另有 `checkin_probe` 固定事件说明。它们只留在本地环缓冲，重启后不保留，不自动上传。诊断失败不会改变提交或状态核验。

日志格式：`probe/1 stage=7 event=failed http=0 ms=246 flags=000000??`。`event` 为 begin/ok/failed/unknown/skipped；`http=0` 表示该事件没有 HTTP 状态，其余为实际响应状态；`ms` 为本次调用开始后的累计毫秒数，最大 120000。阶段表用于定位失败发生在提交前还是提交后，不能仅靠 HTTP 200 或阶段 ok 推断签到成功。等待网络、扫码前会先记 begin；若宿主因总超时或取消硬终止脚本，可能只有末尾 begin 而没有 failed，此时该阶段表示最后等待位置。

| stage | 阶段 |
|---|---|
| 1 | 校验输入/是否选择地点 |
| 2 | 核验学习通账号 |
| 3 | 扫码或取消 |
| 4 | 校验二维码格式 |
| 5 | 提交前查签到状态 |
| 6 | 获取活动与初次要求 |
| 7 | 获取班级/课程关联 |
| 8 | analysis 取握手码 |
| 9 | analysis2 核验握手 |
| 10 | preSign 加载来源页 |
| 11 | preSign 后查状态 |
| 12 | 再次核验活动与要求 |
| 13 | 唯一一次最终提交及响应分类 |
| 14 | 独立查询最终状态 |

`flags` 从左到右固定八位：**定位要求、人脸要求、验证码要求、照片要求、本次选了地点、已尝试最终 POST、独立确认已签到、最近正文的类型已识别**；`1`=是，`0`=否，`?`=未知。要求位只记录服务标志，不记录具体地点；可选照片字段未出现表示未声明照片要求。第六位为 1 而第七位不是 1 时仍可能已提交，不能自动重发。第八位仅表示识别出固定响应类别，不能当作成功证据；第七位为 1 才来自独立状态查询。

探针不输出用户/班级/活动 ID、QR/enc、Cookie/token、设备字段、坐标/地址、完整 URL、响应正文、正文长度或异常原文。缺失要求位继续显示未知并拒绝提交，不通过缺省为 0 来掩盖协议变化。提供日志时同时说明页面显示的固定失败原因；真实账号/活动可用性仍需现场验证。
