## 可复跑合成结果

从仓库根目录运行：

```sh
node school-scripts/xidian-chaoxing/research/schedule-compare.mjs
```

工具运行实际 `scheduleWeek` 模块和独立候选请求；默认每个请求注入 50 ms 延迟、3 次串行样本、两来源交替顺序、并发 1。合成学期仅一门课、一次基本排课页、无调课；现有会话，不包含登录、不命中宿主业务缓存。2026-11-05 本机 Node 24 样本如下，**不是学校测速，也不是手机 QuickJS 性能**：

| 路径 | 每次请求 | 响应体合计 | 3 次耗时 / ms | 中位数 / ms | 数据范围 |
|---|---:|---:|---|---:|---|
| 当前本科教务模块 | 4 | 391 B | 232.09 / 203.30 / 203.34 | 203.34 | 整学期，含调课合并 |
| 超星 `getMyLessons` 候选 | 1 | 236 B | 52.05 / 51.02 / 50.77 | 51.02 | 单周；调课覆盖未知 |
| 当前宿主缓存内切周 | 0 | 0 B | 未计时 | — | 上次成功取得的整学期；沿用原时效 |

这里的差异主要由注入的网络延迟决定；不能将约 4 倍的模型差异写成实际提速。冷登录还要比较 CAS/超星登录、Cookie 建立与失效恢复；缓存命中时当前方案无需出网。`getAllLessons` 未验证之前，不假设它同样只需一次请求就能提供与教务等价的整学期数据。

## 有效会话下的有限真实比较

`--live` 是独立 Node 调试探针，只支持直连和已有会话，不经过手机宿主及 APPTunnel，不自动登录、读取设备库或持久化凭据，不输出账号、课程、Cookie、URL 参数或响应正文。需要操作者在本机为同一学生准备 `ELECON_BENCH_SESSIONS` 环境变量；其 JSON 键为 `xidian.auth:ehall` 与 `xidian.services:chaoxing`（可附 `xidian.auth:ids`），值分别为当前两个脚本已验证的 session record 对象，格式见 [session.js](../../xidian/src/session.js) 和 [service_session.js](../../xidian/src/service_session.js)。不要把变量值写入命令行参数或提交到仓库。

```sh
node school-scripts/xidian-chaoxing/research/schedule-compare.mjs \
  --live --term 2026-2027-1 --week 9 --cx-year 2026 --cx-semester 1 --samples 3
```

默认最多 3 轮，可设置 1–5 轮；总请求上限 100，单次超时 10 秒，重定向逐跳检查固定 origin，失败不自动重跑。输出每轮总时长、请求数/响应字节数、中位数、学期起点是否相同、课程条数及明确的完整性未知状态。两边的账号对应关系须由操作者确认，学期起点和条数相同不能证明课程完全一致。超星业务失败、登录 HTML 或年份/学期不匹配不会被当作快速成功。

真实验收仍需同账号、同学期/周、同网络及设备环境，分别记录已有会话的首次加载、冷登录、缓存命中和切周；逐项核对日期、节次、课程、停课/补课/换教室。本轮未取得可复用的已授权调试会话，未执行真实学校请求。结论是保留教务默认，候选周接口等待完整性与真实耗时验证。
